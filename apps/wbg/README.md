# wbg — 世界观图谱

给自己写设定用的图：人物、地点、势力、事件，以及它们之间的关系。
**命令行就是 API**，AI 可以直接增删改查；**数据就是一行一行的文本**，git 能 diff。

> 这个工具不是复刻某个产品，是同一个目的换一种做法：**让 AI 能全权操作一份世界观**。

## 为什么这样设计

| 取舍 | 选了 | 为什么 |
|---|---|---|
| 数据格式 | **行式文本**（`world.txt`） | AI 直接读写；git diff 友好；出错有行号。JSON 要多一层解析器和转义，收益不成正比 |
| 接口 | **命令行子命令** | 每个命令是一次完整事务（读→改→写），AI 不需要长连接/协议握手；失败就是非 0 退出码 |
| 界面 | 只读（图谱视图） | 人看图、AI 改数据，两边不抢同一份状态 |

## 数据格式

文件：`world.txt`（与 `wbg.exe` 同目录，UTF-8，一行一条）

```
# 注释

@<kind> <name> | <note>        ← 节点
-> <from> <rel> <to>            ← 关系
```

例子：

```
@人 辉夜 | 月之都的公主，持有蓬莱玉枝
@地 月之都 | 云上的都城
@人 蒲岛太郎 | 从月之都归来的渔夫
-> 辉夜 属于 月之都
-> 辉夜 敌对 蒲岛太郎
```

- `kind` 是任意词（人 / 地 / 势力 / 事件 / 物品…），只用来分类，**不参与唯一性**；
- **名字全局唯一**（所以「月之都」不能同时是地名和势力名——要区分就改名，比如「月之都·朝廷」）；
- `note` 可省（省略时 `|` 也省）。

## 命令

| 命令 | 做什么 |
|---|---|
| `wbg ls [kind]` | 列节点（给 kind 就只列这一类） |
| `wbg show <name>` | 一个节点的全部关系（出边 + 入边） |
| `wbg add <kind> <name> [note]` | 加节点（重名拒绝） |
| `wbg link <from> <rel> <to>` | 加关系（两端必须已存在） |
| `wbg rm <name>` | 删节点，**连带删掉它所有的边** |
| `wbg check` | 校验：断裂引用 / 孤立节点；有断裂则退出码 1 |

## AI 怎么用

整份世界观就是一次 `ls`：

```powershell
wbg ls
```

要查一个人物的全部关系：

```powershell
wbg show 辉夜
```

加一批设定（每条都是独立事务，中间失败不影响已完成的）：

```powershell
wbg add 势力 月之都朝廷 "统治月之都的官僚集团"
wbg link 辉夜 效忠 月之都朝廷
```

改完校验，退出码可以直接当判据：

```powershell
wbg check    # 0 = 没有断裂引用
```

## 图谱界面

不带参数运行 `wbg` 就是图谱视图：

- 节点 = 圆（颜色按 `kind` 散列到六色之一），名字画在圆下方；
- 边 = 直线，关系名画在中点旁边；
- 布局 = 简单力导向（150px 内互斥 + 有边的拉近，80 轮后夹回窗口）；
- **拖动节点可以手动调位置**（这一帧只改屏幕坐标，不动 `world.txt`）。

界面**只读**：改数据一律走命令行 —— 人和 AI 不抢同一份状态。

## 还差什么

- 关系类型没有约束（任意词都能当 `rel`）—— 有意为之，先让设定长起来再收；
- 没有缩放/平移（节点多了会挤）；
- 没有版本/分叉：交给 git。
