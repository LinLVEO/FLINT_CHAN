## G1 所有游戏状态（实体池 / 波次 / HUD 数值）想放全局，一处读写
- 想写：`struct E g_es[4];` 或 `struct Game g;`（顶层）
- 报错/限制：`暂不支持 struct 按值全局变量——请用 int 数组自管布局，或在函数里声明局部 struct`（连"全局 struct 指针"也拒，而它的报错文案反过来建议你用全局 struct 指针 —— 文案误导）
- 绕法：全部降级成 `main()` 的局部量（`struct Game st; struct Ent es[4];`），再一层层把 `&st` / `es` 传下去。
- 影响：`main()` 变成 300 行的"数据仓库 + 主循环"，每个 helper 签名里都要多两个参数（`struct Ent *es, int n`）。真正的代价不是丑，是**没法局部重构**：想给某个函数加一点状态，就得改 5 个调用点。全局 `int` 反而可以（lib 里 `gui_*` 一堆），所以"不能有全局状态"是**只对 struct 成立**的半条规则，写起来最容易忘。

## G2 想写 `struct Ent mk_ent(int x, int y)` 之类的工厂函数
- 想写：`struct V mk(int a,int b){ struct V v; v.x=a; return v; }` → `r = mk(1,2);`
- 报错/限制：`struct 须指针返回（struct S *f()——按值返回暂不支持）`
- 绕法：改成 `int ent_reset(struct Ent *e, int x, int y)`（出参指针 + 返回 0/1），调用点写 `ent_reset(&es[i], x, y)`。
- 影响：每次生成实体都要**先声明再传地址**；链式表达式（`foo(mk())`）全写不了。而且"返回成功/失败"和"返回实体"挤在同一个 int 里，语义靠约定。

## G3 想把实体池当作"世界"对象的一个字段：`struct World { struct Ent es[4]; ... }`
- 想写：`struct Pool { struct E es[4]; int n; }`
- 报错/限制：`struct 值字段暂不支持数组形态（v2.4 边界：`struct B b[4];` 不做）`
- 绕法：池必须是**独立的局部数组**，`struct World` 只能存标量指针/标量字段；要访问池只能把 `es` 和 `n` 双参数一路传。
- 影响：这是本轮最痛的一条 —— 它是 G1 的"补刀"：G1 逼你把状态挪进 main，G3 又禁止你把挪出来的东西**打包**。语言允许嵌套 struct 值字段（`struct Body b;` 我能用，见附录），偏偏不允许**数组**形态 ⇒ "实体池"这个最核心的数据结构永远游离在世界对象之外。
- 相关：`struct Ent` 里放 `struct Body b;` / `struct HitStun hs;` **能用**，且 `&e->b` 能传给 `struct Body *` 形参 —— 所以"单个实体"很舒服，"一群实体"很难受。

## G4 敌人状态机想做表驱动：每个状态一个函数，按状态号取函数指针
- 想写：`int run(int (*ops[4])(struct Ent*, int), int n)` → `ops[st](e, d);`
- 报错/限制：`函数指针数组作函数形参暂不支持（v2.6.0 边界）——请传单个函数指针，或在函数内声明数组后逐个赋值`
- 绕法：`if (e->st == T_PATROL) {...} if (e->st == T_CHASE) {...}` 的 if 链（照抄 `lib\enemy.fl` 的写法）。
- 影响：v2.6.0 只做了一半 —— 数组**能在函数内声明并调用**（`int (*ops[3])(int)={&f,&g}; ops[i](10)` 实测能编能跑），但**不能穿过函数边界**。所以"把状态表传进来"这条路封死，表只能写成函数内的局部常量，或者写成 switch/if 链。状态一多（≥6）就会开始复制粘贴。

## G5 `enum` 当 `switch` 的 case 标签
- 想写：`enum TSt { T_PATROL, T_CHASE, T_ATK, T_DEAD }` … `switch (e->st) { case T_ATK: ... }`
- 报错/限制：`case 标签必须是整型常量（case 3: / case -1: / case 'a':）——变量、函数调用、运算表达式都不行（switch 要在编译期排跳转表）`
- 绕法：`enum` 只用它的**值**（`e->st == T_ATK` 完全能编，编译期就折叠成 2），`switch` 全部改写成 `if` 链。
- 影响：`enum` 拿到了"自文档化"的好处，却拿不到"和 switch 配套"的好处 —— 于是最需要 switch 的地方（状态机、事件分发）反而只能 if 链。要么全用魔法数字配 switch，要么全用 enum 配 if 链，**不能两全**。

## G6 HUD 要画文字/数字，但 `gui_text_put` 走 GDI、会和直写 DIB 打架
- 想写：`gui_text_put(&c, "HP 3/5")` 或 `gui_text_put(&c, "R")` 直接叠在像素画面上
- 报错/限制：不是编译错误，是**运行期打架**（GDI 画在 DC 上、我们直写 `Surf.bits` 的 DIB，两套绘制在同一帧里互相覆盖；任务书也点名了"别用 gui_text_put"）。语言侧也没有 `sprintf` / 字符串拼接来现拼文本。
- 绕法：**自己搭 7 段数码管**（`hud_seg(d)` 返回段掩码，`hud_digit()` 用 6 个 `gfx_rect` 画一位，血条直接用 5 个方块，死亡提示的字母 "R" 用 7 个矩形手拼）。
- 影响：任何 HUD 文本都要**自己造字库/字形函数**。这不是"难看"，是"每个新 UI 元素都要先写一个绘图函数"——伤害数字、飘字、菜单、对话，全都要重造一遍轮子。一个"在像素画面上盖字"的库函数（哪怕只有 ASCII 5×7 点阵）能省掉这一整类工作。

## G7 `struct` 数组长度必须写数字字面量（enum 常量、全局常量都不行）
- 想写：`enum K { POOL = 4 }; struct Ent es[POOL];` 或 `int POOL = 4; struct Ent es[POOL];`
- 报错/限制：`struct 数组长度须为数字常量（与 int a[N] 同口径）`
- 绕法：池容量到处写 `4`：`struct Ent es[4];` + `while (i < 4)` ×3 + `atk_apply(es, 4, ...)` + `ent_spawn(es, 4, ...)`。
- 影响：**一个容量数字散落在 6 处**，改池大小要全文搜 `4`（而且字面 `4` 在别处也有语义）。同理 `int map[1020]` 必须手算 `60*17`，`int hbuf[768]` 必须手算 `16*16*3`——没有任何"编译期常量表达式"能帮上忙。这类"没有 `#define`、没有 `const`、没有 `sizeof`"的叠加，让所有数组都变成**手工维护的硬编码**。

## G8 想把三种音效做成表：`char *sfx[3] = {"...jump.wav","...hit.wav","...land.wav"};`
- 想写：`char *sfx[3]; sfx[0] = "games/huiye/jump.wav";` → `audio_play(sfx[i])`
- 报错/限制：`数组暂不能与 &/* 组合（v0.7 单修饰符）`（指针数组整个形态不支持）
- 绕法：每个调用点直接写字符串字面量：`audio_play("games/huiye/jump.wav")` / `"hit.wav"` / `"land.wav"`。
- 影响：路径字符串重复散落，改目录名要搜 4 处。更要命的是**没法做"资源表"**——音效、贴图、关卡路径这类"名字 → 路径"的映射，在 FLC 里只能靠 if 链或者干脆内联。所有路径都是相对 CWD 的裸字符串，也没有 `..\` 之外的路径拼接手段（连 `str([...])` 拼出来的东西都要自己管生命周期）。

## G9 想给实体加个名字/音效路径字段：`struct Ent { char *name; ... }`
- 想写：`struct S { char *name; int v; }` → `s.name = "abc";`
- 报错/限制：`char 指针字段暂不支持（v1.0.5：指针字段仍 int*/double*/结构体指针）`
- 绕法：没有绕法 —— 需要的名字/路径一律内联到调用点，或者换成 `int` 类型的 id 再 if 链映射回字面量。
- 影响：`int *` / 结构体指针字段能用，偏偏 `char *` 不行 ⇒ 实体/配置/资源表里**一个字符串都存不了**。这对"数据驱动的内容层"是硬伤：一张怪的表（名字、音效、掉落）没法用 struct 表达。

## G10 想做"就地初始化"：`struct Ent e = {3, 1, 0, ...};` 或者依赖"没写就是 0"
- 想写：`struct Game st = {0};`（C 的零初始化）或定义个构造函数
- 报错/限制：`struct` 数组**无整体初始化**（`struct S a[2] = ...;` 拒）；局部 `struct` 字段**不清零**（语言已知行为：读未写字段拿脏栈值，见 `docs\语言边界.md` §4 末条）。所以两条路都断。
- 绕法：`main()` 里 15 行逐字段赋值（`st.hp = 5; st.invuln = 0; ...`），`game_reset()` 里再抄一遍 15 行，`ent_reset()` 里 8 行。三处必须**手工保持同步**。
- 影响：加一个字段要改 3 个地方，漏一个就是**静默的脏值 bug**（不报错、表现成"偶尔怪怪的"）。这是本 demo 里最容易被后续改动弄坏的一处。`struct Ent es[4]` 更是必须靠 `game_reset()` 的循环把 4 个槽全刷一遍——万一某个槽漏了，池里就躺着一个"半初始化"的实体。

## G11 没有 `sizeof`、没有编译期常量表达式
- 想写：`int map[60 * 17];` 或 `int need = n * sizeof(struct Ent);`
- 报错/限制：`未声明的变量 'sizeof'`（另外 `struct` 数组长度只吃数字字面量，见 G7，所以连 `60*17` 这种常量表达式都不一定行）
- 绕法：手算：`int map[1020];`、`int hbuf[768];`（16×16×3 帧）、`int ebuf[288];`（12×12×2 帧）。
- 影响：容量和贴图尺寸是**两份真值**（一份在 `sprite_data.fl` 的 `sprite_hero_w()/h()/frames()`，一份在我手算的数组长度里），改贴图尺寸就静默越界。传 `struct Ent *` 时代码里也没法算"第 i 个元素多少字节"来做字节视图。

## G12 想让一个函数返回两个值（敌人这一帧的状态 + 有没有打到玩家）
- 想写：`(st, hit) = ent_update(...)`（元组/多返回值）
- 报错/限制：没有元组、没有多返回值；`struct` 不能按值返回（G2）；`a, b = 3;` 这种逗号表达式也编不过（`期望 ';'`）。
- 绕法：`int ent_update(...)` 用返回值编码"这一帧出手且打到了玩家"（0/1），状态写回 `e->st`；`ent_hurt` 用返回值编码"打死了"，HP 写回 `e->hp`。
- 影响：返回值语义全靠注释和约定，**同一个 int 在不同函数里含义不同**（0/1、槽号/-1、像素数）。多值一多就只能加出参指针，调用点立刻变长、还得自己保证出参非空。

## 附录 A：本轮探针实测**能用**的语言特性（别当成缺口）
| 特性 | 用例 |
|---|---|
| 局部 `struct` 数组 + 元素取地址传 `struct*` | `struct Ent es[4]; ent_reset(&es[i], ...)` |
| **嵌套 struct 值字段**（v2.4） | `struct Ent { struct Body b; struct HitStun hs; ... }`，`e->b.x`、`e->b.vx` 读写正常 |
| **`&e->b` / `&e->hs`（指针→字段取址）** | `body_init(&e->b, ...)`、`hitstun_start(&e->hs, ...)` 都编过；`&es[0].b` 也行 |
| `struct` 数组作形参 + `es[i].b.x` | `ent_update(struct Ent *e, ...)` / `int init(struct Ent *es, int n)` |
| 局部 `for` 里声明循环变量 | `for (int i = 0; i < 3; i = i + 1)` |
| `enum` 常量当值用（不能当 case 标签） | `if (e->st == T_ATK)` |
| 函数内**函数指针数组** | `int (*ops[3])(int) = {&f0,&f1,&f0}; ops[i](10)` |
| 二维 `int` 数组 / 局部数组整体初始化 | `int m[2][3];` / `int a[3] = {1,2,3};` |
| 位运算 / `%` / 一元负号 / `for`+`while`+`break` | 7 段数码管的段掩码全用 `&` 拼 |
| 指针出参（"返回两个值"的替身） | `int split(int x, int *a, int *b)` |
| UTF-8 中文注释 | 源文件里中文注释编译无碍（只要不进字符串字面量） |
