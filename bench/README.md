## 三、判据三条（缺一条就不出倍数）

1. **结果逐位相同**：FLINT / gcc / 独立 Node 实现三份必须一样
2. **回边自证**：反汇编**该实现的入口窗口**，必须有至少一条**向后**跳转 ⇒ 循环真的编进去了
3. **时间下界**：累计 ticks > 50（100ns 级时基下约 5 µs；低于它说明量的是 QPC 调用开销）

## 四、⚠️ 本轮踩的坑（一条都不能再踩）

| # | 坑 | 后果 | 正解 |
|---|---|---|---|
| ① | **归一化口径三份不一致** | FLINT 用 `& (n-1)`、C/Node 用 `% n`，n=2000000 不是 2 的幂 ⇒ 三方必不相等，**误判成"FLINT 算错"** | 统一口径 `x & (n-1)`，**n 必须是 2 的幂**；脚本已加自检 |
| ② | **把 QPF 与 QPC 写进同一个结构体** | 拿 Counter 的低 32 位当频率用 → 报出 3.2~4.3 GHz 的"频率"（每次还不一样），归一化出来的 ns/轮全是错的 | QPF 单独一个结构体；探针 `probe_qpc.fl` 已证明 QPF=10 MHz 稳定 |
| ③ | **文本 cfg 带注释** | FLINT 侧读出 `n=209`（应为 2097152）——把注释里的数字读进来，**静默错** | 改**二进制配置**（4 字节小端），协议唯一、读到什么原样打出来自证 |
| ④ | **拿 RVA 当文件偏移喂 objdump** | 反汇编出来的是 MZ 头 ⇒ 回边数恒 0 的**假红** | 查节表换算（`文件偏移 = RVA − 节VA + PointerToRawData`） |
| ⑤ | **`"--stop-address=($fo + $len)"`** | 双引号里**不求值**，objdump 报参数非法被 `2>$null` 吞掉 ⇒ 空文件 ⇒ 回边恒 0 的假红 | 参数先算成变量再拼 |
| ⑥ | **原生输出收进变量再解析** | 同样的正则匹配恒为 0 条（原因未完全定位） | **落盘再读行**（`Out-File` → `Get-Content`），一次就对了 |
| ⑦ | **`[sbyte]` 转换 >127 抛异常** | 回边扫描整段报错 | 手工算补码（`Sign8`） |
| ⑧ | **长字面量** | FLINT 侧超长十进制字面量有坑 | 分块写（`20 * 1000 * 100`） |

> 共同教训：**尺子自己最容易错**（同族于记忆里「度量工具自己最容易错」）。
> 本轮的 8 个坑里，**6 个都在"测量工具"这一侧**，没有一个是被测代码的错。

## 五、🔒 正式基线（2026-09-19，`N=2097152`，`ITERS=5`，同机同刻）

**判据状态：结果对账 ✅ ｜ 回边自证 ✅ ｜ 时间下界 ✅ ⇒ 倍数可引用**

| 核 | FLINT ns/轮 | gcc -O1 | gcc -O2 | 倍数（flint ÷ O1 / O2） |
|---|---|---|---|---|
| **k1** 依赖链（纯算术循环） | **2.597** | 0.647 | 0.971 | **4.01× / 2.67×** |
| **k2** 数组环走（每轮真读内存） | **5.626** | 1.022 | 1.016 | **5.51× / 5.54×** |
| **k3** 每轮真 call | **7.299** | 0.974 | 不可用（被折掉） | **7.50× / —** |

原始数与逐项判据见 `result-single.json`（每次跑会覆盖）。

**判读（先说清可信度）**：
- 这是**首次可信的跨编译器倍数**：三份实现结果逐位一致、三个实现的入口窗口都有回边、
  所有时间都远高于时钟下界 ⇒ 这些数字可以引用（不是"量到空气"）。
- **k3 最能说明问题**：FLINT 7.3 ns/轮 vs gcc 1.0 ns/轮 —— 一个"每轮一次函数调用"的循环，
  差距主要来自**调用约定/栈帧**（每次调用都要过内存），正是寄存器分配要治的地方。
- gcc 侧 0.65~1.02 ns/轮 ≈ **2~3 个周期**（3.2 GHz）；FLINT 侧 2.6~7.3 ns/轮 ≈ **8~23 个周期**。
  与台账"每步都过内存/过栈、局部变量一个都不在寄存器里"的现状吻合：窥孔把**指令数**压下来了，
  **访存**一点没动。
- ⚠️ `O1/k3` 那一项 gcc 把 call 折掉了（结果对但时间无效），本组按判据 3 已自动剔除 ——
  **不要**去引用 `219015×` 这种数（那是"被折掉"的产物）。

## 六、📊 指令账本：那 4~7.5 倍差距**具体花在哪几条指令上**（2026-09-19 实测）

**k1（依赖链）的内层循环 —— 两侧逐条对照**（反汇编原文，窗口 = 各自的内层循环）：

**FLINT（11 条，其中 8 条访存）**
```
mov  -0x10(%rbp),%eax      ← 从栈上读 x
mov  -0x18(%rbp),%ecx      ← 从栈上读 j
add  %ecx,%eax
and  $0x3fffffff,%eax
mov  %eax,-0x10(%rbp)      ← 把 x 写回栈
mov  -0x18(%rbp),%eax      ← 再次从栈上读 j
add  $0x1,%eax
mov  %eax,-0x18(%rbp)      ← 把 j 写回栈
（循环头，每轮都走一遍）
mov  -0x18(%rbp),%eax      ← 又读 j
mov  -0x8(%rbp),%ecx       ← 读 n
cmp  %ecx,%eax
jge  <出口>
jmp  <循环头>              ← 回边
```
**gcc -O2（7 条，**零**访存；循环头已反转成"底部判断"）**
```
add  %rdx,%rax             ← 三个变量全在寄存器
add  $0x1,%rdx
and  $0x3fffffff,%eax
cmp  %rdx,%rcx
jne  <循环头>
```
> 对照出来的三笔账（这就是优化优先级，不是猜的）：
> 1. **每个变量每次读/写都过一趟栈** —— `mov` 占了 FLINT 指令总数的 **34.8%**，其中 520 条是访存形态；
> 2. **5 条冗余的 `mov` 可直接消掉**（`mov -0x18(%rbp),%eax; add …` 这类"读进寄存器又立刻用"的配对，
>    属**窥孔第二档**的范围，不必等寄存器分配也能拿一部分下来）；
> 3. **循环头没反转**（FLINT 是双跳：`jge` 出口 + `jmp` 回头），gcc 把条件移到尾部、每轮省一条跳转。
>
> 📐 全文件账本（同一次实测）：
> | | FLINT | gcc -O2 |
> |---|---|---|
> | 访存指令占比 | **67.6%** | 64.1%（注：两者窗口都含各自的运行时/宿主代码，**不能直接比**，只能看单项函数；单看 k1 内层循环是 **8/11 vs 0/7**） |
> | push/pop 占比 | 18.4% | 4.1% |
> | 纯寄存器操作占比 | **19.0%** | 11.9% |
> 复现：`& .\指令账本.ps1 -Exe bench_one.exe`（FLINT）/ `-Exe bench_one_O2.exe`（gcc）。

## 六之二、🛠️ 窥孔第二档①「循环头反转」落地前后（2026-09-19，v1.4.17）

**改了什么**（`src\codegen.c`）：`while` / `for` 的条件若是**可重复求值且无副作用**的纯表达式，
就把循环改写成"尾部判 + 单跳"：

```
旧： L_loop: <cond>; jcc.false L_end; <body>; jmp L_loop; L_end:
新： <cond>; jcc.false L_end; L_loop: <body>; <cond>; jcc.true L_loop; L_end:
```
纯度白名单（`expr_is_pure_repeatable`）：只放 常量/变量读/纯算术/纯比较/逻辑非；调用、API、`*p`、数组读、
赋值/自增、取地址、`new` 一律不放 ⇒ 条件不纯时**自动退回旧结构**（行为与 v1.4.16 完全一致）。

**k1 内层循环实拍（新形态，尾巴单跳 `jl`）**：`jge 出口` 之后 body 8 条 → `mov j`/`mov n`/`cmp`/`jge`（尾部）
⇒ **每轮 10 条指令、1 条跳转**（旧：11 条、2 条跳转）。

### 前后对照（**同一把尺子、同一判据，判据全过 ⇒ 可引用**）

| 核 | 改前 ns/轮 | 改后 ns/轮 | 变化 | vs gcc -O1（改前 → 改后） |
|---|---|---|---|---|
| **k1** 依赖链 | 2.597 | 2.596 | **−0.1%**（不动） | 4.01× → 4.01× |
| **k2** 数组环走 | 5.626 | 5.598 | **−0.5%**（不动） | 5.51× → 5.41× |
| **k3** 每轮真 call | 7.299 | **6.269** | **−14.1%** ✅ | 7.50× → **6.43×** |

> 📌 **这组数字本身就是结论**：只少一条跳转 ⇒ 只对**分支受限**的 k3 有效（−14%）；
> 对 k1/k2 **几乎无效**，因为它们是**访存受限**（每轮 8 条 `mov` 过栈）。⇒ **窥孔已见底，剩下的必须靠寄存器分配**。
> 这也把"先做账本、再定优先级"的价值证明了一遍：如果照感觉先做窥孔，会以为还有大空间。

**回归（改后）**：`verify-all.ps1` **ALL GREEN 6/6** —— wx **139/0**、debug **61/0**、回归 **773/0**、boot **213/0**；
`gcc -Wall -Wextra` 警告 **7 = 基线**（零新增）。
**过程中被门抓住的一处真回归**：尾部条件字节让 `-debug` 行表同一行出现两次 ⇒ `dbgcond` 门报
`expected=[9,13,17] addr2line=[9,13,13,17,17]`；处置 = 行记录**保留**（不记会让回边被误报成 body 的行，实测出个 14），
把**门的判据改成集合比对**并在门里写明等价性论证（去重后集合相等 ⇔ 每条 cmp 都真落在控制语句行上）。

## 八、🔀 双编译器差分硬门（2026-09-19 建，周期0 第 5 项）

**为什么**：两台编译器各有一套语义，出过「真 flint 报错、boot **静默通过**并产出零扩展截断的指针」这类分岔。
`boot\verify.ps1` 的第 ⑥ 步只覆盖 **47 个精选样本**，**全量样本没有对账**。

**脚本**：`test\差分门.ps1` —— 全样本扫描，对每个样本比**退出码 + stdout 逐字节**，并按基线判"新增分岔"。
它给每个样本一个判定：`OK` / `DIFF`（都编过但行为不同）/ `BOOT_FAIL`（boot 不支持）/ `FLINT_FAIL` / `HANG` / `SKIP`。

**首次基线（2026-09-19，217 个样本，耗时 82 秒）**：

| 判定 | 数量 | 说明 |
|---|---|---|
| **OK** | **139** | 双端编译 + 行为一致（含 47 个精选差分样本） |
| BOOT_FAIL | **51** | boot 缺特性，**按报错聚类**（下面的缺口簇） |
| FLINT_FAIL | 16 | 全是**故意报错的负例样本**（`inc_*` / `incdup_*` 等，专测 include 错误路径） |
| SKIP | 10 | 开窗/长跑/console 类（GUI 由 wx 门与浮窗自检覆盖） |
| HANG | 1 | `api1`（两侧产物都不自退，单列不算分岔） |

**boot 缺口簇（按 parse err 聚类，这就是自举补齐的路线图）**：

| 缺口 | 数量 | 报错形态 |
|---|---|---|
| **`void` 返回类型** | **18** | `parse err=-183 … text='void'`（`void setv(...)` 这类函数声明） |
| **`for` 的增量是赋值语句** | **5** | `parse err=-192 … text='=' line … for (i = 0; i < 10; i = i + 1)` |
| **引用 `int &r`** | **4** | `parse err=-41 … text='&' line … int &r = x;` |
| **double（浮点轨）** | **7** | `parse err=-183 … text='double'`（boot 侧浮点未接，属既有已知边界） |
| 其余零散 | 17 | err=-82/-139/-50/-53/-48/-51/-55/… 各 1~3 项 |

> 📌 **纪律**：新增 `OK → DIFF/HANG` 的变化 = **红**（这是本门存在的唯一理由）；
> 已列在基线里的 = 已知缺口，随开发逐条收敛（收敛了门上会报"已收敛 N 项"，届时更新基线）。
> **工程坑（都写进脚本注释了）**：① 只拷单个 `.fl` 到孤立目录 ⇒ `include` 全失效 ⇒ **23 个假红**（与真·负例混在一起，很有欺骗性）
> ② 样本里既有同目录 include 也有 `include "../../lib/…"`（**`..` 不做规范化**，FLINT 按字面拼路径）
> ⇒ 副本必须**深度一致**，为此在 `<test>\tmp\lib` 建了 junction 指向 `<root>\lib`
> ③ boot **不吃 `-o`**、产物写在源文件旁边、**无分隔符的相对路径读不了**（err=-2）
> ④ `$PSScriptRoot` 在 `powershell -Command "& x.ps1"` 下**是空串** ⇒ 路径静默退化到 CWD（门会跑空）
