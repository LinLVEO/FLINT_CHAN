## 2. 结构：两处该拆（其余可接受）

| 函数 | 位置 | 行数 | 性质 | 拆的性价比 |
|---|---|---:|---|---|
| `pe_build` | `src\pe.c` | 810 | PE 头／节表／导入表／重定位顺序拼装 | **高**：纯机械拼接，拆成 `emit_dos`/`pe_header`/`sections`/`imports`/`relocs` 几乎不动语义 |
| `gen_expr` | `src\codegen.c` | 754 | AST 节点分发总入口 | **中**：控制流局部多，拆错易出静默错值；要逐节点族搬 |
| `parse_funcdef` | `src\parse.c` | 264 | 函数定义解析 | 低（先不动） |
| `codegen_main` | `src\codegen.c` | 244 | 全局初始化 + 入口 | 低 |
| `codegen_func` | `src\codegen.c` | 242 | 函数体发射 | 低 |

判断：**单趟直接发射、无 IR** 是明确的设计选择（12K 行 vs LLVM 级体量），大 switch 分发是这种架构的常态；
但 750+ 行已越过"读得懂"的线，且 `pe_build` 是**零语义风险**的一刀。

## 4. 语义边界（全部机检，不是口头承诺）

- `docs\语言边界.md`：**58 条**（`probe-cases`），其中 **25 支持 / 33 明确拒绝 / 0 静默缺口**（`probe-gap`=0），
  由 `test\边界探针.ps1` 逐条跑。
- 典型"明确拒绝"（都有报错文案）：
  - 全局初值只吃字面量（`int g = 0 - 1;` 编译失败，要写 `-1`）；
  - 地址值（64 位）不能装进全局 `int`/`char`（报错点在 `src\codegen.c:2513`）；
  - 无 `sizeof`、无 C 风格转型、按值 struct 不能做全局。
- **T1 缺口**（全局槽号与局部帧槽偏移共用一张正整数表）是**已登记缺陷**，规避写进文档：**零新增全局槽**（`docs\语言边界.md` §4）。
- ⚠️ 口径提醒：`int` 数组元素宽度已在 v1.6.5 / v1.7.0 收敛到单点表 `ty_arr_stride`（`src\parse.c:440`）——
  **别再抄"int 数组 = 8 字节槽"的旧数字**（那是 10-25 的状态）。
