## 0. 一句话

**能跑 ≠ 能用 ≠ 能交付**。工业级的标准是：**别人接手能改、改坏了门会红、出问题能回退、性能有预算、失败有人话。**

## 2. 结构（可维护性）

- **`main()` 只做装配**：读配置 → 建窗口 → 主循环 → 收尾。输入处理、状态机、布局计算、绘制各成一个函数；绘制再按区域拆（标题栏 / 侧栏 / 编辑区 / 面板 / 状态栏）。
- **布局常量集中**：`侧栏宽 220`、`行号右界`、`正文起点 268`、`标题栏 34`、`菜单条 26`、`状态栏 26`、`行高` 这类值只允许出现**一处**（函数或常量段），绘制与命中都读它。
- **一个函数一个职责**：函数名能说清"它做什么"；出现"并且/顺便"就拆。
- 当前欠账（2026-10-27 实测）：`studio_win.fl` 4,831 行 / 140 函数，`main()` **1,827 行**；布局字面量 `220`×21、`26`×36、`34`×18、`240`×9、`268`×5。**拆分是 P0，不许再往里堆。**

## 3. 错误处理（不许"不崩就行"）

- 所有系统调用（文件读写 / 内存 / 进程 / 字体 / D2D / 管道）**必须有失败分支**：
  失败要么在状态栏/输出面板给一句人话，要么降级到可用的备用路径（例如 `g_txready=0` 退回 GDI 绘制）。
- 禁止"返回 0 就静默什么都不画"。已知反例（已修）：垫片字体表撑满后 `tx_font` 返回 0 ⇒ `tx_text(id=0)` 直接返回、屏幕一片空白。
- 当前欠账：约 354 处裸调用（忽略返回值）。新增代码不许再添。

## 4. 验收（数字优先）

- 每个功能交付时必须给出**可复现的数字判据**：优先 `ai.state` 的 oracle 行（`ST`/`SC`/`TS`），其次像素计数/字节比对。
- **判据不许重复抄实现常量**（例：探针里不要再写 `lh = fsz + 6`，要从 cfg/`ai.state` 读）。
- 判据必须能"证伪"：写在探针里、失败时输出实际值 vs 期望值。

## 5. 可回退

- 一个提交一件事；提交信息写清**改了什么 / 为什么 / 判据是什么**。
- 动用户可见行为（字号、主题、快捷键、配置项）**先问**，不许先斩后奏。
- 大改动先留旧件（`.old.dll` / 旧 exe），或保证 `git revert` 能干净回退。

## 6. 文档与交接

- 改完更新：`PROGRESS.md` 顶部交接块（事实 + 待拍板 + 恢复命令）、`docs\IDE-功能清单.md`（§0.x 表格 + 判据）、踩坑进 `memory-candidates.md`。
- 文档里写的数字必须是**这一轮实测**的；引用旧数要注明日期。
