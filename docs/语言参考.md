## Abstract (English)

A reference for FLINT as it exists today: lexical rules, the type system and how values
are laid out (32-bit `int` values, 4-byte `int` array elements, 8-byte `int_64`, C-layout
struct fields), statements and control flow, functions and their register/stack argument
split, pointers and arrays, Windows API declarations, and the compile-time limits that
turn into hard errors when exceeded. It also lists the places where the language is
knowingly sharp-edged, and points at the boundary probes as the single source of truth.

## 1. 词法

- **注释**：`//` 到行尾（没有块注释）。
- **标识符**：字母或下划线开头，后接字母/数字/下划线。
- **整数**：十进制，或 `0x` 十六进制。十进制字面量上限 = <!--fact:limit-int32max-->2147483647<!--/fact-->。
- **字符**：`'a'`，值域 0..255（`char` 是无符号字节）。
- **字符串**：`"..."`，支持转义 `\n` `\t` `\\` `\"` 与 `\xNN`（两位十六进制）。
- **浮点**：`double` 字面量（如 `1.5`）。
- **非 ASCII**：源码按 ASCII 处理；中文文案用 **GBK 字节表**逐字节装填（自检：源文件里 >127 的字节数 = 0）。

| 类型 | 含义 | 值宽 / 说明 |
|---|---|---|

**元素排布（写代码前务必记住这四行）**

| 形态 | 每元素字节 | 备注 |
|---|---|---|
| `int a[N]` | **4** | 与 C 的 `int` 同宽；下标按 4 字节缩放 |
| `int_64 a[N]` | 8 | 与 `int` 不同，别混 |
| `uint_32 a[N]` | **4** | 与 `int` 逐字节相同 |
| `uint_64 a[N]` | 8 | 与 `int_64` 逐字节相同 |
| `uint_8 a[N]` | 1 | 与 `char a[N]` 逐字节相同 |
| `double a[N]` | 8 | 下标按 8 字节缩放 |
| `char a[N]` | 1（缓冲） | 帧里按 8 的整数倍给槽，但语义是字节缓冲 |

## 2.1 无符号整数 `uint_8` / `uint_32` / `uint_64`（v1.9.0）

**它们和同宽的有符号类型长得一模一样，只有「怎么解释高位」不同。** 记住下面五条就够用：

1. **算术按 2^N 回绕，不饱和**：`uint_32 a = 0; a = a - 1;` → `4294967295`，再加 1 回到 0。
2. **`/` `%` `>>` `<` 这类用无符号语义**：`(uint_32)0-1 / 2 == 2147483647`；`(uint_32)0-1 >> 1 == 2147483647`；
   `(uint_32)0-1 > 1` 为真。有符号的 `(int)-1 >> 1` 仍是 `-1`（算术右移），两者不冲突。
3. **`uint_8` 参与算术先提升成 `int`**（C 规则）：`(uint_8)255 + 1 == 256`；**回绕只发生在赋值/存储**：
   `uint_8 x = 255; x = x + 1;` → `x == 0`。
4. **混合运算按 C 的通常算术转换**：`uint_32 + int` → `uint_32`；`uint_32 + int_64` → `int_64`；
   `int_64 + uint_64` → `uint_64`；`uint_8 + int` → `int`。
5. **收窄必须显式写转型**（本仓一贯红线）：`int i = 某个 uint_64;` 编译期报错，要写 `int i = (int)u;`。
   窄 → 宽是隐式的，而且是**值保持**的（有符号源符号扩展、无符号源零扩展）。

**显式转型的四个容易记错的行**：

```c
(uint_8)300                    // == 44      （取低 8 位）
(uint_64)(int)-1               // == 18446744073709551615  ← **符号扩展**（C11 6.3.1.3 的值转换）
(uint_32)(int_64)-1            // == 4294967295         （截断取低 32 位）
(int)(uint_32)-1               // == -1                 （同宽位型重解释）
```

**打印**：`print` 与 `str([...])` 都打无符号十进制 —— `(uint_64)0-1` 打出 `18446744073709551615`。

**`char` 与 `uint_8` 的区别**：表示相同、可以互相赋值（不报错、不丢值），但 `print(c)` 打**字符**、
`print(u8)` 打**数字**。

**不支持（编译期硬错，与 `int_64` 同一批边界）**：`uint_64 &r`（引用）、`new uint_64`、
`switch` 条件是 `uint_64`、`uint_64` 的 `^^`、`uint_64` 作 api 实参、`double` 与 `uint_*` 互相隐式转换
（显式 `(double)u` 已开，见上表）。

**还没有的**：`sizeof`、`u`/`U` 后缀字面量（2^64-1 请写 `(uint_64)0 - 1`）。
**boot（自举端）不支持 `uint_*`** —— 属既有类型缺口（同 `double`、`int_64`）。

## 3. 表达式

- 算术：`+ - * / %`；位运算：`& | ^ ~ << >>`；比较：`== != < <= > >=`；逻辑：`&& || !`；三元：`条件 ? a : b`。
- 复合赋值：`+= -= *= /= %=` 等；自增自减：`++` / `--`（前缀、后缀）。
- **没有** `sizeof`；类型转换可用 C 风格转型 `(int)x`（见下）或库函数 `to_int32` / `to_int`。

### C 风格转型 `(type)expr`

写法 = `(` 类型 `)` 一元表达式，优先级与 C 的**一元转换**相同：`(int)x * 2` ≡ `((int)x)*2`，
`(int)(x * 2)` 照括号；`(int)-x`、`(int)x[0]`（后缀比转型紧）都能写。
可写类型：`int` / `int_32` / `int_64` / `char` / `double` / `uint_8` / `uint_32` / `uint_64`，以及它们加 `*` 的指针类型。

| 写法 | 语义 | 机器码 |
|---|---|---|
| `(int)x`（x 是 int / int_32 / char） | 恒等（char 读路径本身已零扩展成 0..255） | 无 |
| `(int)x`（x 是 int_64） | 取低 32 位（同 `to_int32`） | `mov eax,eax` |
| `(int)x`（x 是 double） | 截断向零；越界 = `0x80000000`（同 C 的 `(int)`） | `F2 0F 2C C0` |
| `(int_64)x`（x 是 int / char） | 符号扩展（char 值 0..255，等价零扩展） | `movsxd rax,eax` |
| `(int_64)x`（x 是 int_64） | 恒等 | 无 |
| `(int_64)x`（x 是 double） | 截断向零（64 位）；越界 = `0x8000000000000000` | `F2 48 0F 2C C0` |
| `(char)x`（x 是 int / int_64 / char） | 取低 8 位（模 256，结果 0..255） | `movzx eax,al` |
| `(double)x`（x 是 int / char） | cvtsi2sd（32 位） | `F2 0F 2A C0` |
| `(double)x`（x 是 int_64） | cvtsi2sd（64 位） | `F2 48 0F 2A C0` |
| `(double)x`（x 是 double） | 恒等 | 无 |
| `(T*)p`（p 是任意地址值） | **只换类型**（T = int / char / double / int_64 / uint_N），不产码 | 无 |
| `(uint_8)x` | 取低 8 位（= `x & 255`；T = 任一整型） | `movzx eax,al` |
| `(uint_32)x`（x 是 32/8 位） | 同宽位型重解释（高半本就干净） | 无 |
| `(uint_32)x`（x 是 64 位整型） | 截断取低 32 位 | `mov eax,eax` |
| `(uint_64)x`（x 是 64 位整型） | 恒等 | 无 |
| `(uint_64)x`（x 是 32/8 位整型） | 有符号源**符号扩展**、无符号源零扩展（`(uint_64)(int)-1 == 18446744073709551615`） | `movsxd rax,eax` / `mov eax,eax` |
| `(uint_64)x` / `(uint_32)x`（x 是 double） | 先走 double→int 截断，再按无符号解释 | `F2 0F 2C C0` / `F2 48 0F 2C C0` |

转型结果的类型 = 括号里的类型，之后照常走赋值 / 实参 / `return` 的既有规则（该报错的照旧报）。

**编译期硬错（v1 禁区，不静默猜）**

- `(void)x`、`(struct S)x`、数组转型 `(int[3])x`；
- `(int)p` / `(int_64)p`：地址值是 64 位，装不进 int（T1 边界）；要地址请用指针变量承接；
- `(int*)x` 且 x 不是地址值：整数不能转指针（T1 边界的反向）——空指针请写 `int *p = 0;`；
- `(char)某个 double`：v1 的 double 截断只给了 `(int)` / `(int_64)`，请写 `(char)(int)值` 把两步写清；
- 函数指针转型（代码地址带签名，转成数据指针会丢签名）。

**与旧写法的关系**：`to_int32(x)`（int_64 → int）与 `to_int(x)`（double → int）**保留不动**，
与本表对应行等价；新代码推荐 C 风格转型。`(int_64)` / `(double)` 方向是新开的通道
（此前 `int_64` 与 `double` 互转是硬错）。

**两端差异（诚实边界）**：自举端 `boot\b1_emit.exe` 的类型宇宙只有 `int`(4B) / `char` / 指针 / `struct`，
**没有 `double` 与 `int_64`**（`test\差分门-baseline.txt` 里 8 个 dbl* 样本就是 BOOT_FAIL）。
所以 boot 只支持 `(int)` / `(char)` / `(int*)` / `(char*)` 这几行；`(double)` / `(int_64)` 在 boot 侧
报的是"这个类型不认识"的既有解析错，**不是转型语法没实现**。双端样本 `test\samples\cast1.fl`
只覆盖共用子集（差分门新增分歧 0）。

### 字符串拼接：`str([...])` 与 `str_into(dst, cap, [...])`

```fl
char *s = str(["a=", n]);              // 返回 char*，拼进**唯一一块静态缓冲**
char buf[64];
char *t = str_into(buf, ["a=", n]);    // v2.3.1：buf 是数组 ⇒ cap 自动 = 64
char *u = str_into(p, 64, ["a=", n]);  // dst 是 char* 指针时给三参数（cap 含结尾 0）
```

`str([...])` 只在三个位置可用（指针声明初始化 / `s = str([...]);` / 指针返回函数的 `return`）；
段可以是字面量、`int`、`char`、`double`、`int_64`、`uint_*`、`char *` 变量，`endl` 是段位上的裸换行糖。

⚠️ **别名语义（最容易踩的坑）**：所有 `str()` 共用同一块静态缓冲，`_flint_str_begin()` 第一件事是**清零**它。
所以下面这段**第二行是错的**，而且是**静默错**：

```fl
char *a = str(["P", "Q"]);       // a → 静态缓冲，内容 "PQ"
char *b = str(["X", a]);         // begin() 先把 a 指向的内容清掉 ⇒ b == "XX"，不是 "XPQ"
```

**要拿上一次的结果拼新的，就用 `str_into`**：它先把段拼到内部缓冲，收尾时**一次性拷进你给的 `dst`**，
所以 `dst` 和段永远不重叠（自引用 `str_into(buf, n, [buf])` 也安全）：

| 形态 | 返回 | 失败条件 |
|---|---|---|
| `str([...])` | `char*`（指向静态缓冲，**下次 str() 覆盖**） | 超限/重入 ⇒ **0** |
| `str_into(dst, [...])` | `char*`（= `dst`） | `dst` 不是本函数声明的数组 ⇒ **编译期硬错**；放不下（`cap` = 数组字节数，含结尾 0）⇒ `dst[0] = 0` 且返回 **0** |
| `str_into(dst, cap, [...])` | `char*`（= `dst`） | 放不下 ⇒ `dst[0] = 0` 且返回 **0**；`dst == 0` / `cap < 1` ⇒ 返回 **0** 且**不写 `dst`**（`src\main.c` 的顺序是"先关 sink、再判 dst/cap、最后才写"） |

两者都**绝不静默截断**；`str_into` 的产物归调用方，其它 `str_into` 调用不会覆盖它。

**boot 侧**：`str` 与 `str_into` **双端都支持**（2026-10-24 补齐；2 参数组形态的 `cap` 由 boot 的数组声明推出）。
⚠️ boot 的类型宇宙没有 `int_64`，所以含 `int_64` 段的 `test\facts\f056_str_into.fl` 仍只在真 flint 端跑；
**双端判据 = `test\facts\f057_str_into_core.fl`**（11 位掩码，两侧 exit 42 ＋ stdout 逐字节相同）。

## 4. 语句

- 声明：`int x = 0;` / `int a[10];` / `struct S s;` / `int *p = 0;`
- 常量组：`enum Name { A, B = 3, C };`（v2.1.0；文件级可见；首项 0、后续 = 上一项 + 1；
  显式赋值只认整数字面量/已登记常量/负号+字面量；与全局/函数同名 = 编译期硬错；**boot 端暂不支持**）；
  **enum 常量可直接当 `switch` 的 case 标签（v2.15.0）**。
- 分支：`if (..) { } else { }`
- 循环：`while (..) { }`、`for (init; cond; inc) { }`
- 跳转：`break;`（跳出最内层循环）、`continue;`（for 里先执行增量再判条件，与 C 一致）、`return [expr];`
- 多路分支：`switch (x) { case 1: ... }` —— case 标签 = 整数字面量（可带 `+/-`）**或 enum 常量**（v2.15.0）；
  **不收表达式**（`case 1 + 1:` 仍硬错）
- 错误传播：`try e = f(x);`（v2.0.0）—— 展开成 `e = f(x); if (e != 0) { return e; }`。
  左值必须是**已声明的 32 位整型变量**，所在函数必须返回 `int`；错误值约定 = **非 0**（正负数都算错）。
- **没有** `goto` / 标签。

## 5. 函数

```
int add(int a, int b) { return a + b; }
int *mk(int v) { int *p = new int; *p = v; return p; }
```

- 参数上限 **<!--fact:limit-funcargs-->32<!--/fact-->**：前 4 个走 `rcx/rdx/r8/r9`，第 5 个起走栈参。
- 返回值可以是 `int` / `int_64` / 指针 / `double` / `void`。
- 全局函数表在自举端有硬上限，见 §10；加库函数前先量余量。

## 6. 结构体

```
struct Point { int x; int y; }
```

- ⚠️ **结构体定义后不要加分号**：顶层只接受 struct 定义 / 函数定义 / 全局变量，写 `};` 会报「顶层只允许 struct 定义、函数定义或全局变量声明」（实测 2026-10-20，`lib\*.fl` 里 20 个 struct 也全都不带分号）。
- 字段上限 **<!--fact:limit-structfields-->128<!--/fact-->**。
- 字段按 **C 布局**：`int` 4 字节/对齐 4；指针 8 字节/对齐 8（含 `char *`，v2.12.0）；`double` 8 字节/对齐 8。
- **局部 `struct` 字段不清零**（读未写字段 = 脏栈残值，确定性行为但值不可预期）—— 用前先赋值，或写 `struct S s = {0};`（v2.11.0 起）。
- **全局 `struct`（v2.13.0）**：`struct E g;` / `struct E gs[3];` / `struct E *gp;` 三种形态都支持；
  全局 struct 的**整体初始化仍不做**（`.bss` 全零语义，`struct E g = {0};` 报 `E-LIM-C576`）。
- **struct 数组（v2.1.0）**：`struct Point a[10];` —— 只支持**局部**；长度必须是正整数**编译期常量**
  （字面量 / enum 常量 / 常量表达式，v2.15.0；见 SPEC v2.15.0 节）。
  - 每元素占 `ceil(字节数/8)` 个 8 字节槽 ⇒ **元素步长 = `8*ceil(字节数/8)`**，**不是 C 的 `sizeof`**。
    `struct Point`（8 字节）步长 8；三个 int 的 struct（12 字节）步长 **16**（元素间留 4 字节空隙）；
    含指针字段的 struct（16 字节）步长 16。
  - `a[i].x` 读 / 写 / `+=` / `++` 全部可用；`a[i]` 作表达式 = **元素地址**（可直接传给 `struct S *` 形参），
    `&a[i]` 就是这个地址；数组名 `a` 作实参 = 首元素地址。
  - `a[i].buf[j]`（元素内的定长数组字段）可用；`-strict` 下常量下标越界会报 `E-STRICT-BOUNDS`。
  - **`p[i]`（`p` 是 `struct S *`）2026-10-24 起双端支持**：语义与 `a[i]` **完全同一口径**
    （元素**地址** = `p` 的值 + i×步长，步长 = `8*ceil(size/8)`）⇒ `p[i].f` 读/写、`&p[i]`、
    `p[i]` 直接传给 `struct S *` 形参、`p[i].buf[j]`（元素内定长数组字段）都能用；
    局部声明带初值 `struct S *p = &a[0];` 也补上了（此前**只有形参**能写 `struct S *p`）。
    函数里拿到 `struct S *` 参数后不再"只能碰第一个元素"。
  - **struct 指针字段（v2.3，2026-10-24 双端）**：`struct Node *next;` —— 自引用可以（结构体名在解析字段
    **之前**就登记了）。布局 8 字节 / 对齐 8；`s.next->v`、`s.next->next->v`、`s.next[i].v`、
    `&s.next->v`、`s.next->v = e` 都能用。
  - **struct 值字段（v2.4.0，2026-11-01 双端）**：`struct B b;` —— 内层 struct 必须**已定义**。
    `a.b.x` 读/写、`a.b.x += n`、`a.b.x++`、`p->b.x`（两级指针）、`&a.b`（可传给 `struct B *` 形参）、
    `g(a.b)`（= 传内层地址）都能用；`a.b` 单独出现 = **内层 struct 的地址**（与 struct 变量名同形）。
    布局 = 真实 C：按内层**自身对齐**落位、占内层 size（`int v; struct B{int x,y} b;` ⇒ v@0、b.x@4、b.y@8）。
    **不做**：自嵌套值字段（`struct A { struct A a; }` 尺寸无穷）、前向/互相嵌套（内层必须先定义）、
    整体赋值 `a.b = c`（v2.11.0 只开了变量级 `b = a`）。三层及以上嵌套可用。
    **嵌套数组字段**（`struct W { struct E es[4]; }`）**v2.13.0 起支持**（真 flint 端；boot 未同步）。
    判据：`test\facts\f100_nested_struct.fl`（8 位掩码全亮 ⇒ 42；C 布局用 `int*` 别名独立裁判）。
  - **不能**：`a[0] = b;`（元素整体赋值；v2.11.0 只开变量级 `b = a`）、`struct S a[2] = ...;`（数组整体初始化）、
    `s[0]`（标量 struct 下标）、`a[i].m(...)`（元素上的方法糖，手写 `S_m(&a[i], ...)`）、`p[i][j]`。
  - 判据：`test\facts\f058_structptr.fl`（14 位掩码全亮 ⇒ 42；`facts-run -Compare flint,boot` 双端同码）。
  - 自举端 boot 的 struct 数组（ty=6）与 `p[i]` 均已补齐；容量断点是总槽数 ≤ 99999（见 §11）。
- **struct 值语义（v2.11.0 ~ v2.14.0）**：
  - `struct E e = {0};` 零初始化（只认恰好 `{0}`）；`struct E b = a;` / `b = a;` 值拷贝（浅拷贝，
    按 size 字节搬，指针字段复制指针值）。
  - `char *` 字段（v2.12.0）与局部指针数组 `char *names[3]` 可写；**struct 内**指针数组字段仍不做（`E-LIM-6982`）。
  - 按值返回 struct（v2.14.0）：`struct V mk(int a, int b) { ... return v; }`，隐藏返回指针、内部 ABI
    （不承诺与外部 C ABI 互通）。限制：`mk().x` / `f(mk())` / `int z = mk()` / 丢弃返回值 /
    返回 struct 的函数进函数指针 都是硬错；结构体**按值传参**仍不支持（`E-LIM-C5FE`，用指针/引用）。
  - 仍不做：`sizeof`、struct 转型、元素/字段整体赋值、数组整体初始化、struct 指针数组字段、二维 struct 数组。

## 7. 指针与数组

- `int a[10]`：`a` 作表达式时 = 首元素地址；`a[i]` 等价 `*(a + i*4)`（`int` 元素）。
  长度可以是**编译期常量表达式**（v2.15.0：字面量 / enum 常量 / 括号 / 一元 `+ - ~` / 二元 `+ - * / % << >> & | ^`）。
- **裸指针 `p ± n` 按字节步进**，不是按元素 —— 想按元素走，用 `p[i]`。
- **全局指针是部分边界**：普通全局 `int` 里不许存句柄/地址（全局 `int *p` / `char *p` 仍拒）；
  但 **v2.13.0 起 `struct E *gp;` 可以**（全局 struct 指针）；句柄仍走局部 `int *` 传参。
- 数组可以全局（`char buf[256];`），因为全局槽是静态的；局部数组随函数返回失效。

## 8. 调用 Windows API

```
api kernel32 ptr GetCommandLineA();
api user32 int MessageBoxA(int *hwnd, char *text, char *caption, int type);
```

- 形态：`api <模块裸名> <返回类型> <函数名>(<参数类型>, ...);`
- 模块名写**裸名**（`kernel32`、`user32`），导出时自动补 `.dll`；长度上限 **<!--fact:limit-dllname-->63<!--/fact-->** 字节。
- 导入表：最多 **<!--fact:limit-imports-->96<!--/fact-->** 条 API ／ **<!--fact:limit-groups-->8<!--/fact-->** 组 DLL；单个 API 参数上限 **<!--fact:limit-apiargs-->16<!--/fact-->**。
- 参数类型只比"类型大类"（整型/指针/浮点），不比对具体结构体。

## 9. 内存

- `new` 分配；**`own` / `share`** 接管所有权（`share` 是引用计数）。
- `-safe` 模式强制所有权纪律：`new` 的结果必须被 `own` / `share` 接管，否则编译期报错。
- 默认模式下不强制，靠人守规矩。

## 10. 编译期硬上限

| 项 | 上限 | 何时撞 |
|---|---|---|
| 函数参数 | <!--fact:limit-funcargs-->32<!--/fact--> | 声明/调用超了直接硬错 |
| API 参数 | <!--fact:limit-apiargs-->16<!--/fact--> | 调 Windows API 超了硬错 |
| struct 字段 | <!--fact:limit-structfields-->128<!--/fact--> | 加字段超了硬错 |
| 导入表 API 条数 | <!--fact:limit-imports-->96<!--/fact--> | **软预算**（2026-10-24 起无硬上限：超出照编，只记账/预警） |
| DLL 分组 | <!--fact:limit-groups-->8<!--/fact--> | 同上（软预算） |
| DLL 模块名 | <!--fact:limit-dllname-->63<!--/fact--> | 超了硬错（不再静默截断） |
| 代码段（`.text`） | <!--fact:limit-code-->16777216<!--/fact--> 字节 | 超过硬错（2026-10-24 由 1 MiB 抬到 16 MiB） |

## 11. 已知的尖锐边界

- 全局初始化**只吃字面量**（`int x = 0 - 2;` 会被拒）。
- 没有 `sizeof`；要字节数就手动算或查本文 §2 的表。
- 没有泛型、没有异常、没有 `sizeof`（无符号整型 `uint_8`/`uint_32`/`uint_64` 已有，见 §2）。
- **`try`（错误传播糖，v2.0.0）双端都支持**（boot 自 2026-10-24 补齐；旧缺口码 `-220` 已废弃；双端判据 = `test\facts\f053_errprop.fl`）。
- **`struct S a[N];`（局部 struct 数组，v2.1.0）双端都支持**（boot 自 2026-10-24 补齐；旧缺口码 `-240` 已废弃）。
  ⚠️ boot 的**容量**比真 flint 窄：总槽数 `≤ 99999`（2026-10-24 由 999 抬上来；实测 96,000 槽双端 42、
  104,000 槽 boot 报 `parse err=-241`），真 flint 只受 2GB 帧上限。
  元素步长 = `8*ceil(字节数/8)`，**不是 C 的 sizeof**（见 §6）。双端判据 = `test\facts\f054_structarr.fl`。
- 深水区（自举端函数表 <!--fact:boot-limit-->8192<!--/fact--> 项、boot 的 struct 数组总槽 ≤99999）是**真实容量墙**，加东西前先量；
  导入预算 96/8 自 2026-10-24 起**只是软预算**（导入表按实际用量分配、超出照编，只记账）。
- 完整清单以 `test\边界探针.ps1` 的 <!--fact:probe-cases-->58<!--/fact--> 条用例为准（<!--fact:probe-ok-->28<!--/fact--> 条必须编过／<!--fact:probe-wall-->30<!--/fact--> 条必须硬错）。
