## 0. 先记住三条（这三条决定了你后面会不会白折腾）

1. **必须在仓库根目录执行**。`flint.exe` 要能找到同级的 `lib\`：
   `include "xxx.fl"` 的解析顺序是「**本文件所在目录** → **编译器 exe 所在目录的 `lib\`**」。
2. **别在 PowerShell 里直接写 `gcc src\*.c`**。PowerShell 不给原生程序展开通配符，会变成一个字面量
   `src\*.c` 传给 gcc。要用 `cmd /c "..."`。
3. **`.fl` 源文件不许有 BOM**；中文文案在 FLINT 里是 **GBK 字节**，别直接把 UTF-8 中文写进字符串字面量
   （`winpanel` 的做法是把中文放进 `lang.zh.txt`，源码保持纯 ASCII）。

最小可跑程序长这样（注意 `print` 吃的是**数组**，不是普通函数调用）：

```
int main() {
  print(["hello, flint\n"]);
  return 0;
}
```

### ⚠️ 卡点实测（我第一次就踩了）

我第一条 `cmd /c "gcc -O2 src\*.c -o ..."` 是在**别的目录**下跑的，当场红：

```
cc1.exe: fatal error: src\*.c: No such file or directory
compilation terminated.
exit=1
```

**原因不是命令写错，是当前目录不对** —— `gcc` 找不到 `src\*.c`。
注意 `cd` 和 PowerShell 的"当前位置"可能是两回事，命令前面先 `cd /d E:\FLINT-lab` 最稳。

### 一个诚实的细节：重编出来的 `flint.exe` 和仓库里那份不是逐字节相同的

我连编了两次（同一台机器、同一条命令），两次的 SHA256 **不一样**；逐字节比下去，
**<!--fact:product-flint-->275902<!--/fact--> 字节里只有 2 个字节不同**（当轮原写 250,064 字节；`flint.exe` 每次重建都会变），位置固定：

| 文件偏移 | 是什么 | 两次的值 |
|---|---|---|
| `0x88` | PE 头 `TimeDateStamp` | `00 33 CE 6A` / `12 33 CE 6A` |
| `0xD8` | PE 头 `CheckSum` | 跟着上面那位变 |

也就是说：**gcc 的产物只差一个"编译时刻"戳**，其余逐字节相同。这跟 FLINT 自己的产物不一样——
FLINT 写出的 PE 是**可复现**的（下面 §2 有逐字节证据）。所以本页后面的重编核对才有意义。

```cmd
cd /d E:\FLINT-lab
flint.exe apps\ui_gallery\main.fl -o apps\ui_gallery\ui_gallery.exe
apps\ui_gallery\ui_gallery.exe
```

**实测（编译）**：`exit=0`

```
✅ apps\ui_gallery\main.fl → apps\ui_gallery\ui_gallery.exe （146944 字节，纯自产机器码 PE，未借汇编器/链接器）

**跑起来你会看到**：一个 <!--fact:win-uigallery-px-->420x260<!--/fact--> 的无边框窗口，一屏摆着按钮 `CLICK`、勾选框 `TICK`、
单选 `OPT-A/OPT-B`、进度条 `LOAD 60%`、滑块 `VOL`、可输入框 `focus`、右边一个带滚动条的 `row 1..11` 列表。

**两个实测注意点**：

1. **它会同时开一个控制台黑窗**——因为 `ui_gallery.exe` 是 **CUI 子系统（Subsystem=3）**：
   ```
   ui_gallery.exe   Subsystem 00000003 (Windows CUI)

## 5. 改一行 → 重新编译 → 看到变化

我们用 §4 的画廊练手。**不要直接改 `apps\` 里的原件**（那是仓库的交付物），
把它复制到 `tmp\` 下改，这样随时能扔掉：

```powershell
mkdir E:\FLINT-lab\tmp\mine
copy E:\FLINT-lab\apps\ui_gallery\main.fl E:\FLINT-lab\tmp\mine\main.fl
```

打开 `tmp\mine\main.fl`，找到第 **175 行**，把这一行的**标签文字**改掉：

```diff
-    gui_label(&gc, "FLINT-UI gallery");
+    gui_label(&gc, "FLINT-UI gallery (edited)");
```

然后编译、运行（注意：**源文件换了目录，编译器还在仓库根目录就行**——`include` 会落到 `flint.exe` 旁边的 `lib\`）：

```cmd
cd /d E:\FLINT-lab
flint.exe tmp\mine\main.fl -o tmp\mine\gallery.exe
tmp\mine\gallery.exe
```

**实测（编译）**：`exit=0`，`146944 字节`（和原件一样大——PE 有对齐填充，改文字的字节数会落进填充里）。
**实测（效果）**：窗口左上角变成 `FLINT-UI gallery (edited)`。

我顺手做了个**像素级 A/B** 来证明"变化真的发生了"（同一把尺子：`PrintWindow(hwnd, hdc, 3)` 抓客户区）：

| | 改前（仓库原件） | 改后（我这一行） |
|---|---|---|
| PNG | 6,083 字节 | 6,322 字节 |
| 图像的像素总数 | 109,200 | 109,200 |
| **两次不同的像素** | — | **297 个（占 0.272%）** |
| 变化范围 | — | 只落在 `(151,17)` 起的 **62×13** 矩形里 |

也就是说：**源码里动一行 ⇒ 屏幕上只有那一小块 297 个像素变了，别的地方一个像素没动**。
这就是"改一行看到变化"的机械证据。

### 改完要跑哪道门？（这一步别跳）

改完 app 的绘制代码，按**由近到远**跑这三道：

| 顺序 | 命令 | 是什么 | 什么时候跑 |
|---|---|---|---|
| ① | `pwsh -File apps\ui_gallery\mouse-test.ps1` | 画廊自己的**真鼠标**判据（4 条：真点控件、断 `btn/chk/scr`） | 改了这个 app 就一定跑；**要求桌面安静**（它要注入真鼠标） |
| ② | `pwsh -File apps\ui_gallery\wheel-probe.ps1`、`drag-probe.ps1` | 真滚轮 7 条 / 真拖动 8 条·可加轮 | 改到滚动、拖动、窗口尺寸时跑 |
| ③ | `pwsh -NoProfile -ExecutionPolicy Bypass -File test\verify-all.ps1` | **总门 <!--fact:gate-steps-->14<!--/fact--> 步**：`build / warn / wx / debug / regress / boot / diffgate / audit / eqgate / bench / strict / loop / budget` | 准备提交前跑；**约 8 分钟**，全部 exit 0 才算绿 |

**几条口径**（来自 `README.md` §1 与项目自己的文档）：

- 只改了 **app**：①（必要时 ②）＋ ③ 的总门里 `loop` 那一步（它是**真应用**端到端：编得出来 + 跑得起来 + 输出逐字节对得上）。
- 动了 **`lib\`**（FLGUI 库）：要额外跑库级门 `test\flgui-verify.ps1`，并跑 `test\差分门.ps1` / `test\等价门.ps1` 看有没有把别的产物带偏。

- 想快速自查语言边界：`pwsh -File test\边界探针.ps1`（"说明书说的是真的吗"那套用例）。

## 7. 诚实边界：我没跑成 / 会拦住你的地方

| # | 卡在哪 | 现象（实测） | 怎么办 |
|---|---|---|---|
| 1 | 不在仓库根目录跑 gcc / flint | `cc1.exe: fatal error: src\*.c: No such file or directory`，exit=1 | 先 `cd /d E:\FLINT-lab`；`flint.exe` 要能找到同级 `lib\` |
| 2 | 重编编译器与仓库那份哈希不一致 | <!--fact:product-flint-->275902<!--/fact--> 字节里 **2 字节**不同（`0x88` TimeDateStamp、`0xD8` CheckSum） | 这是 gcc 的编译时刻戳，**不是代码差异**；别拿哈希判断"编译是否成功" |
| 3 | `student` 中文乱码 / 读不到数据 | 数据文件按**相对路径**读 | 从 `apps\student` 跑，或直接用 `run.bat`（它 `chcp 65001` ＋ 切目录） |
| 4 | `ui_gallery` 多一个黑窗 | 它是 **CUI 子系统** | 想要无黑窗就加 `-gui` 重编 |
| 5 | `apps\m2_float\m2_float.exe` **起来就崩** | 事件日志：`atiadlxx.dll` 里 `0xC0000005`（fault offset `0x7ed5c`），窗口停在 200×130 的空窗、从不绘制 | **已知问题**：`test\loop-verify.ps1` 头注释写明——清掉产物 PE 头的 `DYNAMIC_BASE|HIGH_ENTROPY_VA`（`0x0160→0x0100`）即可，原因是本机 AMD 厂商库在镜像随机基址时崩；实测清位后窗口正常长到 187×168 并画出 8 行 |
| 6 | 抓不到带 `-admin` 产物的窗 | `PrintWindow` 一律返回 **False**、图全黑 | 产物内嵌 `requireAdministrator` ⇒ 它跑在提升会话，非提升进程发 `WM_PRINT` 被 **UIPI** 拦掉。要么用提升的会话抓，要么用不带 `-admin` 的复刻产物 |
| 7 | 行数统计悄悄少了 | `Get-Content \| Measure-Object -Line` 把 263 行的文件读成 **201 行** | PowerShell 5.1 的 `Get-Content` 默认 ANSI，UTF-8 中文后的换行会被吃掉；用 `[IO.File]::ReadAllLines($p).Count` 或 `-Encoding UTF8` |
| 8 | 长套件 / 真鼠标门 | 本次任务里被工单禁止 | 你自己在**桌面安静**时跑；命令见 §5 的表 |
