FLINT 的标准库**不是预编译库**：`lib\` 下的一组 `.fl` 源文件就是标准库。程序用
`include "xxx.fl"` 把某个模块的源码并进当前编译单元，编译器和这些源码一起产出 PE，
没有独立的链接步骤，也没有随编译器分发的 `.lib` / `.dll`。

`include` 的解析顺序是**当前文件所在目录 → 编译器 exe 所在目录的 `lib\`**。因此装在
`flint.exe` 旁边的库，程序里写 `include "str_lib.fl"` 就能直接用，不必拷贝路径。

## Abstract (English)

This document is the guide to FLINT's standard library: a set of source-level `.fl`
modules under `lib/`, pulled into a program with `include`, never precompiled or linked.
It lists every module with its purpose and public entry points, then shows a complete
minimal program built from the dynamic-string and number modules. It closes with the
conventions the sources actually state: NUL-terminated byte strings, caller-owned
buffers, allocation ownership for `Buf` and `Str`, views that never copy, fixed-slot
containers, and the language limits that shape these interfaces. Every quantity is
either omitted or taken from the project's fact meter, so the page cannot silently
drift.

## 用法示例（最小可编译程序）

把下面的程序存成任意目录下的 `stdlib_demo.fl`，用 `flint.exe stdlib_demo.fl` 编译：
两个库都是自包含的（互不 include），`include` 会回退到编译器旁的 `lib\`。

```fl
// stdlib_demo.fl —— 动态字符串 + 数字格式化
include "dstr_lib.fl"
include "num_lib.fl"

int main() {
  struct Str s;
  s.p = 0; s.len = 0; s.cap = 0;          // 未初始化态 = 指针为 0，必须先清零再 init
  if (std::str_init(&s, 0) < 0) { return 1; }

  char num[16];
  std::itoa(2 + 3, num);                   // 写十进制并补结尾 0；缓冲由调用方给
  std::str_add(&s, "2 + 3 = ");
  std::str_add(&s, num);

  char *out = std::str_s(&s);              // NUL 结尾，可直接当 char* 用
  print([out, "\n"]);                      // print 收一个数组
  std::str_free(&s);
  return 0;
}
```

程序输出 `2 + 3 = 5`。

同一个模式可以换成任何模块：`include "io_lib.fl"` 后用 `std::file_read` 整读文件；
`include "vec_lib.fl"` 后用 `std::vec_new` / `std::vec_push` 装任意定长槽；需要哈希表时
`include "map_lib.fl"`。**不要**再把被依赖的库单独 include 一次（例如用了 `vec_lib.fl`
就不要再 include `mem_lib.fl`，用了 `ui_lib.fl` 就不要再 include `num_lib.fl`）——
FLINT 的 `include` 没有守卫，重复并进同一份源码会撞重复定义。

## 约定与已知限制

以下每一条都能在对应 `.fl` 文件头的注释里找到出处；这里只做索引，不发明规则。

### 字符串与缓冲

- **`char*` = 以 0 结尾的字节串**。`std::strlen` / `strcpy` / `strcat` / `strstr` 都按这个
  约定工作；二进制数据不要依赖结尾 0，要用带长度的接口。
- **长度语义与 NUL 语义是两回事**：`std::file_read` 返回读到的字节数但**不补 0**；
  `std::esc_json` 收的是“指针＋长度”；`std::slc_at` 对内嵌 0 原样返回。把长度数据当
  字符串打印前，调用方要自己留位并补 0。
- **缓冲由谁给**：`str_lib.fl` / `fmt_lib.fl` / `num_lib.fl` / `mem_lib.fl` / `esc_lib.fl` /
  `slice_lib.fl` 都**不分配内存**，缓冲由调用方给，容量也由调用方保证。`fmt_*` 是位置
  游标式，不检查容量；`std::itoa` 需要调用方留够十进制位数，`std::itohex` 需要留够
  十六进制位数（具体见函数上方注释）。
- **库内静态缓冲是覆盖语义**：`std::cn_ansi` 返回库内全局缓冲，下一次调用立刻盖掉上一次
  的结果；容量用 `std::cn_ansi_cap()` 取，别手抄。要留住结果必须自己先拷走。该入口
  不可重入；`std::cn_to_ansi` / `std::cn_to_ansi_n` 无隐藏状态。
- **`esc_lib.fl` 有工作区上限**：单次输出超过上限会返回 `-1`（不截断），调用方要解更长的
  串请分块调用；容量常量在文件头与 `esc_json` 内同步。

### 所有权与生命周期

- **`Buf` / `Str`**：块由 `std::buf_init` / `std::str_init` 分配，由 `std::buf_free` /
  `std::str_free` 释放（都幂等）。`std::buf_s` / `std::str_s` 返回的指针**归容器所有**；
  任何会扩容的调用之后它立即失效；调用方不许自己 `VirtualFree`。
- **不许自追加**：把 `std::buf_s(&b)` / `std::str_s(&s)` 的返回值再喂回 `buf_add` /
  `str_add` 会因扩容先释放旧块而悬空。要自追加先把内容拷进临时缓冲。
- **`Slice` 不拥有内存**：`std::slc_mk` 只记“基址＋偏移＋长度”；原串被改写或释放后切片
  立即失效。`slc_mk` 不做越界检查（它拿不到原串真实长度），越界责任在调用方。
- **`Vec` / `Map` 按地址搬运定长槽**：`std::vec_push` 可能搬家，返回值必须写回
  （`v = std::vec_push(v, &x)`）；只保留拷进去的那份字节，不要留传入的地址。
  `std::vec_get` / `std::map_get` 返回的是**槽地址**，要拿满整槽请按地址 `memcpy`，
  不要用 `p[0]` 当完整值读。
- **`Map` 的键是拷贝**：`map_put` 立刻复制键字节，调用方的临时缓冲之后怎么变都不影响表。

### 数字与宽度

- **`int` 的宽度在语言里分几处口径**（变量/数组元素、`struct` 字段、指针下标的步长与
  读出宽度并不相同）。因此本组库内部一律把 `int*` 字段先赋给 `char*` 局部变量再逐字节
  存取，**不要自己在结构体指针字段上做 `p[i]` 算术**——那会静默错位。
- **算术按 32 位截断**：`Buf` / `Str` 的 `len` / `cap` 按 32 位口径计算，库内显式设了单块
  容量上限，超限一律**响亮返回 `-1`**，不静默越界（上限常量见 `buf_lib.fl` /
  `dstr_lib.fl` 文件头）。十进制字面量上限是 <!--fact:limit-int32max-->2147483647<!--/fact-->，
  更大的常量请写十六进制。
- **`std::abs` 对最小的负整数返回自身**（与 C 相同）；`std::percent` 在 `total <= 0` 时返回 0。

### 文件、网络与平台

- **`io_lib.fl` 是整文件一次读写**：读返回字节数、不补 0；写返回是否全部写入。文件大小
  走 32 位口径，超大文件不在支持范围；流式句柄用 `std::open` / `std::read` / `std::write` /
  `std::seek` / `std::tell` / `std::eof`（见文件头）。
- **`http_lib.fl` 只面向本地只读接口**：只支持 IPv4 字面地址（不做 DNS）、HTTP/1.0 ＋
  `Connection: close` 读到对端关闭；无 TLS、无 POST、无重定向、不解析 `Content-Length` /
  chunked。JSON 侧只做“按键取数”，不建树；数值按定点整数返回。
- **`std::http_get` 的输出参数与读取不要放进同一次调用**：先把结果写进变量，下一句再读
  （文件头把这条列为实测坑）。

### 语言侧约束（这些约束塑造了库的接口）

- 函数形参/实参上限 <!--fact:limit-funcargs-->32<!--/fact-->；库接口超过这个量级时改用
  “结构体 in/out”（`http_lib.fl` 的 `struct HttpBuf` 就是例子）。
- `struct` 字段上限 <!--fact:limit-structfields-->128<!--/fact-->。
- **全局不支持指针**，`struct` 不能当全局变量；文件/字体/窗口句柄只能走局部 `int *`。
  库的全局载体只用标量或 `char` 数组。
- 没有 `#define` / `const`，所以库里的容量常量是“函数返回值或字面量＋注释”的形式
  （例如 `std::cn_ansi_cap()`、`esc_ibufcap()`），改容量时按注释里列出的同步点一起改。
- `include` 无守卫：库文件要么自包含，要么显式 include 自己的依赖；**用户只 include
  最上层那一个**。
