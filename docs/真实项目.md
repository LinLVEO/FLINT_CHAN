## Abstract (English)

This file is the measured account of FLINT's real applications: the flagship panel, the
control gallery, and the hardware float window. FLINT_CHAN, called FLINT for short, is
an in-development language centered on Windows desktop development, aiming at Zig, C++,
and Rust. Each project is described by what it does, which libraries it uses, how it is
built and measured, and which checks stand behind it. Screenshots are included, and the
measurement method is stated next to the results so that the same figures can be
reproduced. Read it when you want evidence that the language carries real tools rather
than samples.

## 3. `apps\m2_float` —— 硬件监视浮窗

- **是什么**：TOPMOST + LAYERED + 无边框的硬件读数浮窗，8 行（FPS / CPU / GPU / RAM / DISK / NET / FAN / 功耗），窗口尺寸按行内容自适应（实测 187×168），右键弹中文菜单，位置与开关存 `config.json`。数据由**同进程缝合**的 C# LHM 桥给（`HwBridge.dll` 走导入表直调）。
- **用哪些库**：`lib\flgui_win32.fl`（→ `flgui_widgets.fl` / `ui_lib.fl`）＋ 自己的 8 个模块 `hw.fl`、`stitch.fl`、`float_rows.fl`、`menu.fl`、`menu_gen.fl`、`config.fl`、`netfmt.fl`、`glyph.fl`（它们再拉 `lib\` 的 `math_lib.fl`、`http_lib.fl`、`fmt_lib.fl`、`num_lib.fl`、`str_lib.fl`、`io_lib.fl`、`ui_lib.fl`）。
- **源码规模（实测）**：`apps\m2_float\*.fl` 共 **<!--fact:app-m2float-allfl-->2940/145101<!--/fact-->**（行/字节）（其中 `main.fl` = **<!--fact:app-m2float-mainfl-->794/45266<!--/fact-->**（行/字节））。
- **产物（实测）**：`apps\m2_float\m2_float.exe` = **<!--fact:product-m2float-->241664<!--/fact--> 字节**，子系统 = 3（CUI），**内嵌 `requireAdministrator` 清单**。
  同一个源不带 `-admin` 重编 = **241,152 字节**（差的 **512 字节**就是那份清单；两次都 exit 0）。
- **怎么跑（实测过，且**踩到真问题**）**：
  ```cmd
  cd /d E:\FLINT-lab
  flint.exe apps\m2_float\main.fl -admin -o apps\m2_float\m2_float.exe
  apps\m2_float\m2_float.exe
  ```
  ⚠️ **实测：直接跑这份产物会崩**。事件日志里两条一样的记录（21:29:05、21:30:19）：
  `m2_float.exe` 在 **`atiadlxx.dll`**（AMD 厂商库）里 **`0xC0000005`**，fault offset `0x7ed5c`——
  所以窗口建出来是 **200×130 的空窗、从不绘制**（`PrintWindow` 返回 False、非背景像素 = 0）。
  **这是已知问题，不是新缺陷**：`test\loop-verify.ps1` 头注释写得很清楚——清了产物 PE 头的
  `DYNAMIC_BASE|HIGH_ENTROPY_VA` 就好，"原因不在代码生成，是这台机器有 AMD GPU，`atiadlxx.dll`
  在镜像被随机基址加载时 0xC0000005（只翻那两个字节、不重编就能换过/不过）"。
  我按这个做法复刻了一份（**清位 0x0160 → 0x0100**）+ 去掉 `-admin`（否则见下面的 UIPI 边界），
  窗口正常长到 **187×168** 并画出 8 行读数 ⇒ 图 `docs\图片\m2_float-浮窗.png`。
  另一条实测边界：**带 `-admin` 的产物跑在提升会话里时，非提升的抓图进程 `PrintWindow` 一律返回 False**
  （UIPI 拦 `WM_PRINT`）——只有去掉清单、两边同一完整性级别才抓得到。这正好是上面"复刻"的第二个理由。
- **判据（9 条，在哪）**：`test\loop-verify.ps1`（**<!--fact:test-loop-verify-loc-->312<!--/fact--> 行**）——真应用端到端冒烟门：用 `flint.exe` **和**自举编译器
  `boot\b1_emit.exe` 各编一遍 `apps\m2_float\main.fl`，清 ASLR 位，用 app 自己的 `dump.on + demo.on` 自检开关跑起来，
  再把两份 dump **逐字节**比（掩掉 `tick=` / `dp=` 这类活值），**9/9**。
  用法与出处：`lib\FLGUI.md` §"浮窗冒烟（loop 线）" = `pwsh -File test\loop-verify.ps1`。**我没跑**（工单禁止长套件）。

## 一句话总结"外人看得见"的部分

三个 app 都是**一个源码目录进、一个单文件 exe 出、没有安装器也没有运行时依赖**；
`winpanel` 与 `ui_gallery` 的产物我已经用文档里的命令**逐字节复现**过；
`m2_float` 的源码也编得过、跑得起来，但**仓库里那份产物在这台 AMD 机器上会被厂商库的 ASLR 崩溃挡住**
（项目自己的门是清位绕过的）。这就是目前真实的边界，没有藏。
