# FLINT 设计决策（编号化）

> **这份文件是什么**：把项目里**已经定下来**的设计决策抽成编号条目，供外人**引用和讨论** —— 想说"某条不合适"时，直接说"**D几**"即可。
> 每条四行：**决定 ／ 理由 ／ 影响面 ／ 怎么验证或去哪看**（有必要的条目会再追加一行 `⚠️ Agent 自决` 或 `TODO`）。
>
> **纪律（本文的写法就是证据）**
> - **每条必须有出处**（文件 + 节/行号）。**找不到出处的一律不写** —— 需要补的标 `> TODO（待补出处）`。
> - **不许自己发明决策**：本文只**转写**已经在仓库里成文的东西。**措辞、命名、项目对外的名字**这些口径项**不属于本文范围**，拿不准的标 `> TODO（待拍板）`。
> - **编号只追加、不重排**（D1…Dn 是给外人用的锚点；删条目可以把编号留空，别挪号）。
> - 标了 **⚠️ Agent 自决** 的条目 = **不是所有者拍板的**，可以被推翻；标了「用户定 / 用户拍板」的条目出处里带日期或原话。
>
> **一句话怎么用**：想参与 → 挑一条 D 说"这条我有意见"；想实现 → 第四条给了"去哪儿验"。

### D1 · 编译器本体全自产：不借 LLVM、不借汇编器与链接器、不背 C 运行时

- **决定**：从源码到 PE 的每一步都自己做 —— 词法、语法、代码生成、PE 写出全部在 `src\` 里自产；不引入 LLVM 之类的现成后端，不调用 `as`/`ld`，产物不链接 CRT、不带运行时。
- **理由**：这个项目存在的目的就是验证「一个人、一台老机器，能否从零走通 **源码 → 手写机器码 → 自产 PE → 自举**」这条路（**走通是资产，走不通也是资产**）。顺带换来三条可见的好处：产物小（`hello` 含打印 = 3,072 B）、冷启动无初始化、没有运行时依赖。
- **影响面**：性能优化、指令选择、重定位、符号表这些**全都要自己写**；新增一个指令形态（例如浮点的 SSE 路径）要自己写编码；也不能靠换后端"顺手提速"。反面代价同样记在账上：**用不了 C 生态的库**，只能按 `api` 声明直调 DLL 导出函数。
- **怎么验证 / 去哪看**：`SPEC.md` 使命节（"从零走通 源码 → 手写机器码 → 自产 PE → 自举"）｜`README.md` §顶部（"不借 LLVM、不借汇编器、不借链接器、不借 C 运行时"）＋ §3 目录表（`src\` = 编译器本体）｜`开源前-人类可用性缺口.md` §2-A6（无 CRT / 无运行时 = 本钱，也是限制）。

### D2 · 缝合分两维，两本账分开记：语言账 ≠ 借用账；借了必须登记，没记 = 没发生

- **决定**：**自己搓不出来的就用现成的**（这叫缝合），但分两维 —— **实现缝合**（借轮子：库/服务/命令行工具）与**特性缝合**（把别人已验证过的好特性缝进语言）。**产品/工具层可以借；语言能力不因"别人有"而砍**。凡"借用"或"参考"（不分层：构建期工具／运行期库／只读抄口径／抄算法）**一律记进 `FLINT明细.md`**。
- **理由**：目标是「**究极缝合战士**」＝ **缝合能力 ＋ 零运行时**；而缝进来的东西必须是「**已有定论**」的（有先例／成文规范／官方文档）—— 查不到的才值得自己试。两本账分开，是为了防止"因为别人有好用的，就把自家语言能力砍掉"。
- **影响面**：每条借用必须写清 谁提供／版本／**许可**／怎么用／**为什么不自己搓**／回退兜底（静态缝合 GPL 系会传染产物 ⇒ 许可必须逐条查证）；交火面必须是**可替换的窄接口**（接别人与自研两条路能互换 ＝ 可回退），借来的火力点必须有**降级兜底**。
- **怎么验证 / 去哪看**：`SPEC.md` 设计原则 8｜`FLINT明细.md` 文件头（两本账 ＋ 四条纪律 ＋ "没记 = 没发生"的硬性规则）。

### D3 · 只走编译期缝合，不背运行时；三条守门线不许破

- **决定**：缝合只有两条路，**FLINT 只走编译期** —— 别人编译好的 DLL／库当作"**系统库**"用，在**导入表里写一条**（调用点 `call [rip+disp]`）；**运行期缝合**（解释器／`dlopen` ＋ 查表 ＋ GC，每帧付过路费）**不做**。代价按频率分档：**每帧路径**只许库级／静态缝进来，**中低频**（如 500ms 一次读数）走进程级，**启动期一次性**怎么省事怎么来。**三条守门线**（缝多少都不许破）：① 产物仍是**裸 PE**（不依赖运行时／框架／安装包）② **无 GC、无常驻大内存** ③ **冷启动没有初始化阶段**。
- **理由**：运行期缝合会把「自产裸 PE ／ 无运行时 ／ 冷启动无初始化」这三条本钱**烧掉一半**。判据一句话：**"用了进程级不丢人，每帧跨界才丢人"**。
- **影响面**：标准库薄是**故意的**（不是懒）；IPC／JSON 这类"中低频跨界"是**被允许**的常规手段；反过来，任何"每帧调一次外部进程"的设计在架构上就不成立。
- **怎么验证 / 去哪看**：`SPEC.md` 设计原则 9、原则 10｜`可用性路线图-人机两条线.md` §4（明确不做：通用转译工具包、把 DLL 塞进 exe 资源节运行时加载）｜`开源前-人类可用性缺口.md` §4（无 GC／无运行时 换三条本钱）。

### D4 · 基础特性自己实现；缝合只用在"确实没招了"的地方；**"参考"只抄口径、不抄实现**

- **决定**：语言基础特性照 `SPEC.md` 原则 5 长，**缝合只用在"确实没招了"的地方**；对成熟项目的态度分两档 —— **只读参考**（抄口径/做法，**不链接、不引入依赖**）与**算法蓝本**（照着重写，例如 FLGUI 参考 microui 的设计）。**绝不把别人的实现引进构建链**。
- **理由**：**门面不能建在别人的二进制上**。样板已经写死在文档里：Dear ImGui 只抄它的 **immediate-mode 理念** ＋ "GUI 可以极小无依赖"这个证明，**绝不引其 C++ 实现**（引进来会拖 C++ 运行时／链接器 → 破原则 10 的守门线）；引用的替代物 = 自产的 FLGUI。
- **影响面**：UI 库、字符串/容器/格式化这些"本该有现成库"的东西**都得自己长**；好处是每一个都能被"一个人读得完"这条尺子量（对标 rxi 的 **microui 那一格**，约 1,100 行 C，**不逐项对齐 Dear ImGui**）。
- **怎么验证 / 去哪看**：`SPEC.md` 设计原则 8（Dear ImGui 那段）＋ 长期目标节（FLGUI 的对标对象与"抄架构不抄实现"）｜`FLINT明细.md` §三（只读参考表，"参考"的样板那一行）＋ §四·五（FLGUI 的借用/参考登记，含**不借清单**）｜`开源前-人类可用性缺口.md` §4 末行（"基础特性自己实现"＝标准库薄是故意的）。

### D5 · 近期走**形态 A**（别的语言出 DLL、FLINT 产物导入表直调）；**形态 B**（静态缝合单文件）后置、单独立卡

- **决定**：近期目标 = **一条命令 → 别的语言产出 DLL → FLINT 产物导入表直调**（产物 = exe ＋ 若干 dll）。**形态 B（真打包成单文件／静态缝合）后置**，只有确认"必须单文件分发"才开刀。且「一条命令」**先长在构建层**（脚本／工程描述），**先不搬进 `flint.exe`**；语言完善与这条线**并行、不互相等**。
- **理由**：① 形态 A 今天已经通了（`HwBridge.dll` 就是）；② 用户要的是"语言更好用"，不是"单文件分发"；③ 形态 B 要写"吃 `.obj`/`.lib`"的静态缝合，是编译器里**最重**的一件（要动 PE／重定位／符号，得走全部门：双端／自举不动点／差分门）。④ 先例：Rust 的 `build.rs + cc`、Zig 的内嵌 clang、Nim 的"翻 C 再编"—— **"吞别的语言"是构建系统的职责，不是语言特性**。
- **影响面**：交付形态默认是"exe ＋ 若干 dll"（**不是**绿色单文件）；构建入口先做成脚本／工程描述；`api` 声明生成器必须带**分层**能力（否则"生成即烧预算"，见 D1 与导入上限）。
- **怎么验证 / 去哪看**：`可用性路线图-人机两条线.md` §1（**D1~D4** 四条已定口径）＋ §3 的 P2/P3（验收 = "一条命令 ＋ 三个断言 ＋ 一次通过"；P3 明确"只有形态 A 走不通时才启动"）｜`FLINT明细.md` §四（`COFF`/`.lib` 静态缝合 = 究极形态、最重）。
- ⚠️ **Agent 自决**：该文件 §1 自述这四条是"**Agent 自决，可随时被用户推翻**"（`可用性路线图-人机两条线.md` §1）—— 它是**技术层的工程判断**，不是所有者拍板的方向项。

### D6 · 单平台、单目标：只有 **Windows 10 x64 PE**；**明确放弃 Win7**

- **决定**：只有 Windows x64 一个目标；支持底线 = **Win10 打底，明确放弃 Win7**（不为兼容老系统收手）；跨版本兼容性改为**编译期可断言的 Win10 下限**。
- **理由**：所有者 2026-09-25 拍板，出处原话是「**不为兼容老系统收手**」；跨版本兼容性改为**编译期可断言的 Win10 下限**（落地方式由交接块记录）。
- **影响面**：只有 Windows x64 这**一个目标**（无跨平台目标）；老系统不承诺；所有"平台相关"的设计（分层窗口、DPI、manifest）都默认 Win10 x64 语义。
- **怎么验证 / 去哪看**：`SPEC.md` 现行定位节（**支持底线（2026-09-25 用户拍板）**）＋ 长期目标节 目标 C 段末（"支持底线 = Win10（放弃 Win7）"）｜`开源前-人类可用性缺口.md` §2-A2（单平台单目标）｜`README.md` §顶部事实表（平台行）。

### D8 · 判据文化：**判据先写 ／ 每步验证 ／ 独立裁判 ／ 验收不外包**

- **决定**：在本项目里**争论不靠嗓门，靠一条能跑的用例** —— ① 动手前**先写"什么算做完"**（能跑的命令 ＋ 期望数字）；② 每步**先跑再写**，用输出说话，不用"应该能行"；③ 实施者报的数字**只当"待核事实"**，由**另一次独立运行**复测；④ **验收绝不外包**（谁验收谁自己跑）。
- **理由**：两条真踩过的教训 —— **"跑绿了"不等于"对了"**（判据本身也会错，见过"门全绿但用户一眼看出界面是空的"）；**同一条命令在不同负载下结论不同**（依赖墙钟的判据会间歇假红 ⇒ 复现必须写清环境）。所以"提一条判据"被定义为**一次贡献**，而"能双向失败"被当成判据的合格线。
- **影响面**：项目真正的三种通信介质 = **工单**（`工单-*.md`，一次活的完整形状，缺一件就退回）／**判据**（`test\` 的门与探针，"对话本身"）／**交接块**（`PROGRESS.md` 头部，任何人随时接手的锚点）。对外承诺随之而来：**每个结论都能指到一条可跑的命令**，**每个改动都有回退点**，做不到/没验/不知道**一律明写**。

### D9 · 命名与口径：**先给候选、由所有者拍板**；实施方不自行定名、不悄悄改口径

- **决定**：新关键字／库函数／API 别名**一律由实施方给候选**（每个附「便利性 vs 可读性」权衡 ＋ 影响面），**所有者拍板后才落地**。涉及**命名／口径／是否砍特性**的争议找所有者拍板，**不和实施方私下拉锯**。所有官方库函数统一挂在 `std::` 命名空间下。
- **理由**：词法宪法是「**便利性第一**」（短、熟、少打字、一眼看懂，"纯洁/一致/字面直白"冲突时一律让位），而"哪个更便利"是**品味判断，属所有者**；命名基本不可逆。另一半理由是协作结构本身：**所有者不做"人 ↔ AI 之间的翻译"**，所以任何需要转达的东西**必须写成文件**。
- **影响面**：任何"顺手起个名字"的实现都是违规；`print`／`itoa`／`strlen` 这类"惯用短名保留"是这条规则的产物；`README.md` 顶部那句"一句话定位"**至今空着**就是这条规则在起作用（只有所有者能给措辞）；项目对外名字也与已有项目重名、公开前要过一遍。
- **怎么验证 / 去哪看**：`SPEC.md` 设计原则 7（含"取名必须问用户"＋ 词表审计表）＋ 标准库节的命名规则（`std::` 前缀、"任何新名字先给用户候选"）｜`docs\协作协议.md` §1（三个角色："所有者不读代码、不写代码"是有意设计）＋ §5（涉及命名/口径 → 找所有者拍板）＋ §7 未定项清单｜`README.md` 顶部（"待拍板：这一行只有项目所有者能给措辞"）。

### D10 · `int` 是 **8 字节槽**（**语言语义，不是 C 的 `sizeof`**）；跨语言交换先对齐元素宽度

- **决定**：`int` 的宽度在**三处**分岔，写代码前必须分清 —— ① **变量／数组元素／栈帧槽 = 8 字节**；② **`struct` 字段 = 真实 C 布局**（`int` 字段 **4 字节 / 对齐 4**）；③ **指针下标 `p[i]` = 4 字节元素**。跨语言传数组/缓冲区前，**先逐条对齐"一个槽几字节"**。
- **理由**：这是**语言语义**（编译器内部读写一律 ×8，完全自洽），不是 bug；但**同名的 `int` 和 C 的 `int` 不是同一个东西**。历史上为此栽过：用 C 的 4 字节 `int` 去填 FLINT 的 `int a[4]`，**只生效两格**（`7 7 0 0`）；换成 8 字节宿主类型才严丝合缝。
- **影响面**：① 通用容器在无泛型下的现实形态 = **8 字节槽 ＋ 取地址传值**（`v = vec_push(v, &x)`；C 式"int 槽擦除"被有意堵死）；② 从打包槽里拆字节**一律 `% 256` ＋ 负数兜底**（裸 `%` 对 −31 给 −31，不是 193）；③ 结构体字段类型要**照抄头文件**（指针字段必须带 `*`，否则"地址是 64 位装不进 4 字节"）；④ 缝合的接口两侧要**对位自证**（逐槽读回打印对账），别只看"值像不像" —— 错位时最容易"个别值看着对"，把问题藏得很深。
- **怎么验证 / 去哪看**：探针用例 `slot_byte_split_mod256`（`test\边界探针.ps1:83`）与 `vec_slot_roundtrip`（`test\边界探针.ps1:85`）｜`SPEC.md` 类型节（`int[N]（数组，N 个 8 字节槽）`）＋ `struct` 节（字段真实 C 布局）＋ 指针节（`*(intPtr + n)` = 4 字节）｜`FLINT明细.md` §4.5「跨语言接口纪律」（缝合前必看；含"宿主的一个槽几字节"这条判据）｜`开源前-人类可用性缺口.md` §3-B3（"`int` 宽度四处分岔 … 同族已栽三次"）。
