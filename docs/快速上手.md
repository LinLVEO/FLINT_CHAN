## Abstract (English)

A hands-on walkthrough from a fresh clone to a running program. It covers the Windows
toolchain, building the compiler with one `gcc` command, compiling and running the hello
example, how `include` resolves, how to run the five bundled examples, and how to run the
gates that keep the docs honest. It ends with the five traps that cost us the most time:
BOM in source files, GBK for non-ASCII text, PowerShell wildcard expansion, the
compiler-relative `lib/` lookup, and the absence of `argv`.

## 1. 构建编译器

```cmd
cd /d <你的仓库路径>
cmd /c "gcc -O2 src\*.c -o flint.exe"
```

约 9 秒，**没有任何输出**（gcc 不啰嗦），产出 `flint.exe` = **<!--fact:product-flint-->276414<!--/fact--> 字节**（⚠️ 每次重建这个数都会变，它是"这次构建"的读数）。

验一下编译器活着：

```cmd
flint.exe
```

不给源文件时退出码 1，并打印用法（这是正常的）。

## 2. 第一个程序

新建 `hello.fl`：

```
int main() {
  print(["hello, flint\n"]);
  return 0;
}
```

```cmd
flint.exe hello.fl
hello.exe
```

**注意 `print` 吃的是数组字面量**（`print(["..."])`），不是普通函数调用 —— 这是 FLINT 的固定形态，不是笔误。

## 3. include 怎么找文件

`include "xxx.fl"` 的解析顺序（**先近后远**）：

1. **当前源文件所在目录**
2. **编译器 `flint.exe` 所在目录的 `lib\`**

所以：库文件放 `lib\`，程序里的 `include "str_lib.fl"` 即可；把 `flint.exe` 挪到别处时，同目录要带上 `lib\`。

## 6. 五个必踩的坑

1. **`.fl` 源文件不许带 BOM** —— 带 BOM 的 UTF-8 会让词法器第一行就错。
2. **中文别直接写进字符串字面量** —— FLINT 源码按 ASCII 处理，非 ASCII 文本要用 **GBK 字节**装填（真实项目的做法：中文放 `lang.zh.txt`，源码保持纯 ASCII）。
3. **不要用 PowerShell 直接写 `gcc src\*.c`** —— PowerShell 不给原生程序展开通配符，会变成字面量 `src\*.c` 丢给 gcc。用 `cmd /c "..."` 或显式列文件。
4. **`flint.exe` 与 `lib\` 的相对位置** —— 见 §3，挪 exe 时最容易忘。
5. **没有 `argv`** —— 命令行参数要自己从 `GetCommandLineA()` 里抠（`examples\exitcode` 与 `examples\filecount` 各有一份现成写法）。

## 7. 报错现场怎么留

跑挂了想留证据，用仓库自带的记录器（**失败才落盘，成功零噪音**）：

```powershell
node tools\错误记录.mjs build examples\hello\hello.fl      # 编译失败才记
node tools\错误记录.mjs run apps\m2_float\m2_float.exe    # 运行失败才记
```

日志落到 `errors\<时间戳>-<模式>.log`：命令、工作目录、退出码、stdout/stderr、源文件哈希与前 60 行摘录；`errors\索引.md` 是总目录。提 issue 时直接贴这份日志。
