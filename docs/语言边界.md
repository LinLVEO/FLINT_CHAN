# FLINT 语言边界

> **这份文件是什么**：把编译器"**能编什么 / 明确拒绝什么 / 哪里还在静默出错**"写成一张人类可读的表。
> **真值源不是这份文件**，是能跑的探针：`test\边界探针.ps1`（当天 **38 条**用例：支持 18 ／ 明确拒绝 20 ／ 已知静默缺口 **0**）。
> 本文每一行的"期望"都是从该脚本的用例定义（`kind` / `code` / `err` / `note` 字段）**逐条转写**的，并在「出处」列给出该用例的行号。
>
> ⚠️ **诚实声明**：本表最初转写时**没有在本机复跑**这份探针（当时那一轮不允许跑编译/门/探针）。
>   **2026-10-13（B1-3 那一刀）已复跑：38/38 全绿、exit 0**（同轮把原来的 1 条 `gap` 收成了 `wall`）。
>   想拿到实测结果，跑 §3 那条命令。
>
> **一句话概述**（这门语言的形状，按重要程度排）：
> - **语法是 C 的子集，类型层不是**：`int` / `char`（无符号字节）/ `double` 三种，**没有泛型**、**没有无符号整型**、**没有异常**、**没有 `sizeof`**、**没有 C 风格转型**、**没有 64 位整数变量类型**（64 位值用 `int *` 当容器，或让 api 声明成 `ptr` 返回）。
> - **`int` 是 8 字节有符号槽** —— 和 C 的 `int`（4 字节）**不是同一个东西**：变量/数组/栈帧槽 = 8 字节，`struct` 字段 = 真实 C 布局（`int` 4 字节），指针下标 `p[i]` = 4 字节元素。拆字节一律 `% 256` + 负数兜底。
> - **函数参数 ≤ 32**（前 4 个走 `rcx/rdx/r8/r9`，`double` 走 `xmm0-3`，第 5 个起走栈参，求值顺序**右→左**）。
> - **`struct` 字段 ≤ 128**（2026-09-27 由 64 抬到 128）。
> - **导入表硬上限 96 条 API ／ 8 个 DLL 分组**；**导入模块名（写出名）≤ 63 字节**（含自动补的 `.dll`；2026-10-13 B1-3 起超长是**默认档编译期硬错**）；**boot（自举编译器）的函数表 512 项，当前余量 = 0**（再加 1 个库函数就编不过）。
> - **非 ASCII 文本不能做字面量**：中文要走「UTF-8 源 → GBK 逐字节十六进制表 → 生成器 → 自检」这条链，**每个标签一个构建步骤**。
>
> ⚠️ 最后三条（导入上限 / boot 余量 / GBK 字节表）**探针里没有对应用例**，出处见 §4；写着"探针未覆盖"的地方别当成"探针验过"。

## 0. 三类结论怎么读

探针把每条用例归成三类，**每类都有实质断言**（不是"编译成功就算过"）：

| 类别 | 本文写法 | 含义 | 怎么算过 |
|---|---|---|---|
| `ok` | **支持** | 语言**支持**这件事 | 必须编过，**且产物退出码 == 期望值**（支持这件事也得行为对） |
| `wall` | **明确拒绝** | 一座**明确挡住的墙** | 必须**编译失败**，且错误文案里含关键词 |
| `gap` | **已知静默缺口** | 已知的**静默**缺口（编译过、行为不对） | 必须**能编过** —— 一旦有人修好它，这条会**变红**，提醒回来订正本表 |

⇒ 这套设计的要点：**放宽了会红、收紧了也会红**。所以本表"过期"这件事是**可被发现**的，不用靠人记得。

## 2. 这张表的"已知不安静"处（写下来免得下一个人重踩）

1. **用例 23（`global_struct_ptr`）的报错文案在误导**：它拒"全局 struct 指针"，而拒它的**同一条规则**在被拒时建议的正是"用 struct 指针全局变量"。⇒ 正解 = 局部 `struct` + 指针传参。

3. **脚本自身的编排小瑕疵（不影响判据）**：用例 19（`ptr_local_var`，`kind='wall'`）物理上排在"ok：语言支持"那一节里（`test\边界探针.ps1:47` 的节标题之下、`:63`）。**按 `kind` 判它是墙**，只是位置容易看错。
4. **两个"静默缺口"计数别弄混**：本节说的是**探针里的 `gap` 用例数**（现在是 **0 条**）；`开源前-人类可用性缺口.md` §3-B1 数的是**人因清单**（升级为"产品缺陷"后剩 3 条，B1-3 已清）。两者**不是同一份清单**。

## 6. 维护纪律

- **改了编译器行为 ⇒ 同轮改这张表**；改了这张表 ⇒ 跑一次 §3 的命令（全绿才算改对）。
- **新边界优先做成探针用例**（`ok` / `wall` / `gap` 三类之一，**每条都要实质断言**），再补进本表；只有"编译器报错覆盖不了"的（预算/容量/双端）才写成别的仪器并在 §4 登记。
- 本表的**行数与类别计数必须与脚本一致**：写"38 条"就真的是脚本里 `.n=` 的条数（`kind='ok'` 18 ／ `kind='wall'` 20 ／ `kind='gap'` 0）。
