# 部署说明 —— 浮窗（m2_float）＋ 缝合桥（HwBridge.dll）

> 面向：以后要跑这个浮窗、或要重建 `HwBridge.dll` 的人（包括将来的我）。
> 权威细节：`FLINT明细.md` §4.7（TLS 三条件）／§4.8（缝合交付）／§4.9+（PresentMon 帧率通道）。本文件只讲**怎么跑、怎么建、怎么退**。
> 更新：2026-09-17（v1.4.7 桥内置 PresentMon 帧率通道；交付目录多一个 `PresentMon.exe`）

## 一、它是什么

FLINT 自产浮窗（纯自产机器码 PE，不借汇编器/链接器）**同进程**缝进一个 C# 库当数据源：
`HwBridge.dll` = 用 **LibreHardwareMonitor 0.9.2** 按「零微软工具」配方编出来的原生 DLL（NativeAOT Shared），
由 FLINT 产物的**导入表直调**（`api "HwBridge.dll" …`）。⇒ 浮窗**不再需要外部 C# 版进程、也不需要 8080**。

**分工（比"整个搬过来"更重要）**：桥只补 FLINT 自己拿不到的那几项 —— **CPU 温度/频率/功耗（读 MSR）＋ GPU 显存 ＋ FPS**；
**内存 / 磁盘 / 网速仍走 FLINT 本地直读**（桥给这些槽位留 `v_=0`，行构建器自动跳过）。

**FPS 的来源（v1.4.7 起）**：桥内**起外部 `PresentMon.exe`（Intel 开源、ETW 系统级）并解析它的 stdout CSV**，
口径对齐 C# 参考版的 `FpsMode=presentmon`；**RTSS 共享内存退化为回退**（PresentMon 无数据时才用）。
顺带把"来源进程名"也取回来了（FPS 行末尾的 `·msedge` 那种标注）——**8080 JSON 里没有这个字段**，
所以这个标注只有缝合路径给得出来。

## 二、跑起来（三步）

1. **产物目录必须是这一份**：`E:\FLINT-lab\apps\m2_float\`
   里面有 `m2_float.exe`（**用 `flint -admin` 构建**，产物内嵌 `requireAdministrator` 清单）、`HwBridge.dll`、
   **`PresentMon.exe`**（帧率通道要用；缺了不会崩，只是 FPS 回退到 RTSS/`--`）。
2. **确认开关**：`E:\FLINT-lab\tmp\row-probe\stitch.on` 存在 ⇒ 走缝合桥。
   ⚠️ **不要**同时存在 `http.on`（那会退回 8080 取数）；`demo.on` / `dump.on` 是**自检开关**，平时不要留。
3. **起窗口**：`m2_float.exe` 带 admin 清单 ⇒ **不能用 `& exe` 直接起**（会报 `The requested operation requires elevation`），
   要用 `Start-Process -Verb RunAs`（本机 UAC 静默，不弹窗）。

> **缺 `HwBridge.dll` 会怎样**：导入表在**启动期**解析 ⇒ 进程直接起不来（窗口不出现）。
> 一键构建脚本的 `-Verify` 就是拿这条当**反向判据**（把 DLL 挪走 → 必须起不来；挪回 → 必须起来）。

## 三、重建 `HwBridge.dll`（一键）

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "E:\FLINT-lab\libcs\hwbridge\一键构建.ps1"
# 窗口正在跑（DLL 被占用）时只想编译不改部署：
powershell -NoProfile -ExecutionPolicy Bypass -File "E:\FLINT-lab\libcs\hwbridge\一键构建.ps1" -NoDeploy
# 连"起不起得来"的正反两条判据一起验（会起窗口，验完自己关掉）：
powershell -NoProfile -ExecutionPolicy Bypass -File "E:\FLINT-lab\libcs\hwbridge\一键构建.ps1" -Verify
```

脚本做的事（每步都有输出与退出码）：**先决条件检查 → 重建垫片 `crtshim.obj`（含 `-DSHIM_INIT_MODE=4`）＋重生成 `altnames.rsp`
→ 清 `obj\…\native` / `out` / `bin` → `dotnet publish` → 产物断言（**逐条点名** 12 个必需 `hw_*` 导出 ＋ **TLS 数据目录必须存在** ＋ 产物必须比 `crtshim.obj` 新）
→ **`PresentMon.exe` 就位（哈希比对）** → 部署到 `apps\m2_float\`（SHA256 比对）**。

配方依赖（全 NuGet，**零微软工具**）：`Microsoft.DotNet.ILCompiler` 8.0.30 ＋ `runtime.win-x64.Microsoft.DotNet.ILCompiler` ＋
`LLD.Link.Toolsets.win-x64`（lld-link，替代 VS 的 link.exe）＋ `Microsoft.Windows.SDK.CPP.x64`（461 个 `.lib`），
垫片/工具在 `E:\FLINT-lab\tmp\cs-aot-probe\`（`shim\` ／ `sdk\` ／ `lld\` ／ `tools\gen-altnames.ps1`）。

> ⚠️ **新增 `.cs` 必须登记进 `HwBridge.csproj`**：该工程 `<EnableDefaultCompileItems>false</EnableDefaultCompileItems>`，
> 默认不扫描目录。2026-09-17 踩过：`PresentMonFps.cs` 没登记 → 编译器报 `CS0103 当前上下文中不存在名称 PresentMonFps`，
> **症状像命名空间写错，实际是文件根本没进编译**。

### ⚠️ 三条不能碰的红线（碰了就回到"间歇崩"）

1. **垫片前置 TLS 块大小 0x1000 绝不能动** —— 托管侧（ILC）把 Thread 地址写成**常数 0x1020**，原生侧是**链接期**算的；
   改前置块 ⇒ 两侧各认一个 Thread 对象 ⇒ 致命错误 `attempted to call a UnmanagedCallersOnly method from managed code` ＋ 随机 AV。**要撑大只能往 `.tls` 尾部加。**
2. **TLS 数据目录必须有**（垫片的 `_tls_used`；脚本会断言，缺了不许发）。
3. **不要自己调 `RhInitialize`**，也不要给 DLL 指定别的入口：初始化走官方姿势（`.CRT$XCU` 只登记回调，运行时在**第一次** reverse pinvoke 自己初始化）。

## 四、帧率通道（PresentMon）—— 怎么验、怎么查

**三档降级（写死的行为，别指望"永远有值"）**：
PresentMon 有帧率 → 用它（`FLAGS bit4=1`，来源名可用）；没有 → RTSS 共享内存；再没有 → 显示 `--`（窗口照常活）。

**最快的自证手段**：同目录建一个 `HwBridge.pmdebug.txt`（**空文件即可**）⇒ 桥开始写调试日志
（`start:` / 参数 / stderr / `swept orphan …` / `结果: fps来源=… 状态位=0x…`），验完**删掉**它即关闭。

**专用验尸台**（不走窗口、直接按 FLINT 的 ABI 调桥）：
- `libcs\hwbridge\pmcheck.c` → `pmcheck.exe <HwBridge.dll> <日志> [秒数]`：四项断言（子进程起得来／FPS 与 1%low 有值／
  `hw_pm_src` 真把进程名写进**调用方缓冲**／`hw_pm_stop` 收得掉子进程），退出码 0 = 全过。
  ⚠️ 它用 **`long long b[24]`** 而不是 `int b[24]`：FLINT 的 `int` 是 8 字节槽，这是 ABI 的可执行参照。
- `libcs\hwbridge\pmprobe\`：更早的探路工具（先证明"从 .NET 托管进程直起 PresentMon + 解析 stdout"这条路走得通）。

**造渲染活动**（PresentMon 只统计真 Present，**GDI 重绘不算**）：
- `tmp\d3dprobe\`（源码 `libcs\hwbridge\d3dprobe.c`，gcc 编）：迷你 D3D11 swapchain 窗口，`d3dprobe.exe 60` 跑 60 秒。
  **验证帧率通道就靠它** —— 别再用浏览器开窗口造活动（2026-09-17 因此开了一堆 Edge 窗口，打扰用户，已停用）。
- `tmp\render_probe.fl`（FLINT 自产）：GDI 重绘窗口，**验证"来源标注"够用**（能产生窗口帧给 DWM），但**不足以**让 PresentMon 出帧率。

**会话名（ETW）为什么每次都不一样**：`PresentMonHWBRIDGE<PID>_<tick>`。历史坑：
默认名 `PresentMon` 会和参考版**互相抢**（两边都 `--stop_existing_session`，最后两边都没数据）；
固定专属名又会**撞自己上次被强杀留下的残留会话**（日志里是"will be stopped"之后一行数据都没有）。
唯一名同时绕开这两件事。可用同目录 `HwBridge.pmsession.txt` 固定前缀（排查用）。

## 七、已知边界（诚实标注）

- **PresentMon 只统计真 Present（D3D/DXGI）**：只有 GDI 重绘的窗口不产生帧 ⇒ 那种情况下 FPS 会是 `--`（这不是缺陷，是 ETW 的口径）。
  实测：msedge 的 DSH 页面 143~144 fps；`d3dprobe.exe` 143.4 fps。
- **1% low 需要 ≥60 帧样本**、平均帧率需要 ≥10 帧（与参考版同门槛）；采样窗口 900 帧（≈15 秒@60fps）。
- **ETW 要提权**：本产物带 admin 清单 ⇒ 子进程自然继承；非提权时 PresentMon 只能看到部分进程（探针实测会有 `<unknown>` 条目）。
- **CPU 三项（温度/频率/功耗）要提权**（读 MSR 走 Ring0 驱动）；非提权时窗口仍能起（本地通道 + GPU 项照常显示）。
- 本机 **Defender 会把自造 PE 归因成 `VulnerableDriver:WinNT/Winring0`** ⇒ 已加**目录级**排除 `E:\FLINT-lab`（文件级无效）。
- 字号/行宽与 C# 参考版仍有已知差异（GDI 量宽 ≈15%），见 `浮窗规格-对C#逐细节.md`。
